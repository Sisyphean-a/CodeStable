# 通用工作技能

给单一用户的日常助手：直接处理文档、调研、分析和整理，通过自然交流逐渐理解用户，减少反复介绍背景和整理文件的负担。它独立于仓库原有编程技能，不需要安装 `cs-*`，也不是后台记忆服务。

## 六个能力

| 技能 | 使用场景 |
| --- | --- |
| [work](skills/work/SKILL.md) | 编写、修改、分析与整理，交付实际结果并验证 |
| [check](skills/check/SKILL.md) | 独立只读检查，指出错误、风险和遗漏 |
| [grill-me](skills/grill-me/SKILL.md) | 已获同意的集中访谈，可聊画像、规划或方案 |
| [memory](skills/memory/SKILL.md) | 维护短工作约定、事实背景、旁观画像、口语和合作关系 |
| [record](skills/record/SKILL.md) | 维护工作知识、业务口径、规则和已确认决定 |
| [setup](skills/setup/SKILL.md) | 显式初始化、检查或迁移用户级知识库 |

日常不必依次运行技能；普通疑点短问，集中访谈先征得同意，检查并修改直接由 `work` 完成。初始化只由显式调用的 `setup` 承担，不在每个仓库重复执行。

## 安装与首次使用

使用支持 Agent Skills 的宿主或安装器，安装本目录 `skills/` 中的六个技能及各自参考，并保留同级关系。安装位置由宿主决定；无需复制工作区模板、安装整个仓库或把技能放入知识库。安装器须定位本套独立来源，不能从仓库根误选原 `cs-*` 集合。

如果使用 [skills 安装器](https://github.com/vercel-labs/skills)，在本仓库根可从本地来源全局安装，交互选择目标宿主（此安装方式需要 Node.js）：

```sh
npx skills@latest add ./general-work -g --skill work --skill check --skill grill-me --skill memory --skill record --skill setup
```

全局安装是否受支持以所选宿主为准；安装器处理技能加载，`setup` 不安装自己，也不修改宿主配置。

安装后，在宿主中显式调用 `setup`，要求初始化当前电脑用户的知识库。AI 会核实真实用户主目录与权限，现场生成统一知识入口；已有记录保留。之后可以在不同仓库或文件目录执行任务，无需逐仓库初始化。

数据位置、项目隔离与读写约定以[上下文协议](skills/memory/references/context-model.md)为准。知识、原稿副本和内部临时材料集中在用户级知识根，不回写技能源码。个人背景可复用，项目口径仍有独立范围，同名仓库不自动合并。

迁移旧知识时，显式调用 `setup` 并指定旧来源；它保留旧文件，冲突会询问。若宿主仍加载指定旧记忆根的规则，须先解决入口冲突，不能把两套规则都当成现行依据。

宿主须能加载技能，工具须能访问用户本机的知识根；访问不到时明确阻塞，不改用当前仓库或远程工具账户存储。后续技能调用会读取相关记录，不代表所有闲聊都自动加载。技能不是后台服务、安全沙箱或加密存储。

## 日常使用

可以直接说：

- “把这份 PPT 改成适合客户沟通的版本。”
- “检查这个表的口径和公式，先不要改文件。”
- “我们专门聊一次，让你更了解我的工作和规划。”
- “这是我长期合作的伙伴，以后沟通方案考虑这个关系。”
- 显式调用 `setup`：“初始化我的用户知识库。”
- “把刚刚确认的业务口径保存下来。”
- “看看这个选择里，我可能忽略了哪些角度，别为了安慰我而附和。”
- “你现在记得我哪些偏好？”或“忘掉那条理解。”

是否长期保存依据[上下文协议](skills/memory/references/context-model.md)，不是说过的话全部记。事实和观察分开；私人敏感信息与客户机密须有保存授权，概括也不例外。你可以随时纠正理解；忘记只保证受控记忆的核实清理，不保证删除宿主聊天或外部历史。

正式 Word/PPT/Excel 成果由 `work` 制作，工作知识由 `record` 维护；内部记录和副本无需你整理。默认备份指定原稿后原地修改文件，不擅自扩大修改或对外发送。

## 用日常话留下工作习惯

你只需说“以后周报先写结论，再列风险”。AI 确认长期适用范围后，负责在用户知识根的 `working-rules.md` 保存一句约定，例如：**周报：先写结论，再列风险。** 只有本次适用就不长期保存，拿不准时只问一句，不让你自己整理规则文件。

这相当于给 AI 一份短工作备忘：本套技能执行前先读，跨项目复用，但只应用匹配范围的约定。你可以说“这次例外”“以后改成这样”或“忘掉这条”；个人协助习惯不混进性格画像，客户或业务规范仍归对应知识页。

你不必理解或编辑 `AGENTS.md`，AI 只在必要时用一句人话说明已保存什么。这里没有修改宿主全局配置，也不保证未调用本套技能的每条闲聊自动读取。

## 了解用户，不迎合用户

用户知识根中的 `profile.md` 保存明确背景、目标与价值或生活偏好，协助方式约定只存 `working-rules.md`；有依据且有长期价值时，才创建 `portrait.md` 保存思维、情感及性格倾向的旁观理解。两者不互相复制，画像有场景、依据和不确定性，不是客观人格判定或心理诊断。

画像用于发现取舍中的盲点、价值冲突和不同视角，不用于取悦、操纵、无端批评或替你作主；你的价值与偏好可以参与取舍，但不会改变事实或硬约束，也不会为了凑出你爱听的结论暗改判断标准。没有画像也能正常工作，你可以查看、纠正或忘记这些观察。具体方法见[旁观画像](skills/memory/references/observer-model.md)。

长期记录优先保存有未来价值的量级、趋势及必要口径，而非逐月营销金额等原始数值；会改变判断的预算、阈值和其他关键精确数据仍保留。所有长期页合并重复、替代过期内容，不堆流水账，也不为压缩删掉关键约束、反例或不确定性。原始材料、正式成果和恢复副本保持请求所需的完整性。

## 文档随使用完善

AI 读取已有知识时，会主动修正能确定修法的旧结构、重复记录和索引问题，适配当前实际加载的技能规则，不必你另行发起整理。只处理当前相关范围，先留可恢复的临时副本，核实后清理；保留关键内容，不为改版虚造事实或改写你的长期要求。

只读任务不改文件；有歧义、需要重组整个库或改变宿主入口时先确认。它不自动更新技能源码，也不遍历重写全部知识；无法修复或恢复时如实说明。具体纪律见[文档维护与版本适配](skills/memory/references/maintenance.md)。

## 工具与验证

配置可实际操作文件的 MCP 或其他工具；这套技能不绑定某个工具，也不附带 Office 引擎。需要验证内容、数据公式、可编辑结构及相关版面，具体依据见 [Word](skills/work/references/documents.md)、[PPT](skills/work/references/slides.md) 和 [表格](skills/work/references/spreadsheets.md)。

文件保存成功不等于公式已重算或版面已检查。缺少备份、编辑、重算、渲染或记忆读写能力时，AI 应具体说明阻塞和待验证项，不能模拟成功或默默换成交文字、截图。部署时先用获准的样本检查这些能力，再用于重要文件。

## 维护检查

在仓库根执行下列命令，检查技能声明、工作约定与画像归属、按需维护入口及只安装技能后的参考可达性；技能本身运行不依赖 Node.js。

```sh
node --test general-work/test/skills.test.mjs
```

这些是静态与安装结构检查，不证明模型一定遵守规则，也不代替目标电脑上的实际初始化、跨仓库读取、迁移、Office、MCP、备份恢复或隐私权限验证。
