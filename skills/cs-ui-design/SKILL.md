# 界面设计

本技能拥有设计结果，不拥有代码实现。用户当前只想把模糊产品意图或整体偏离感变清楚时交给 `cs-goal`；任务只是把已有设计准确落地，或要求在同一任务直接交付可运行结果并把设计委托给 Agent 时，交给 `cs-feat`。只有用户要独立探索、创建或改变界面设计时才继续。

## 1. 判定模式

选择一种模式：

- **新设计**：没有现行视觉方案，从目标和约束建立设计语言。
- **演进**：保留品牌、信息架构和识别性，定向改善现有界面。
- **重做**：用户已允许改变视觉语言，但仍要显式列出保留项。

先读取可用的 Figma、截图、品牌资产、设计系统、现有页面和内容。它们是约束，不是灵感素材；已有设计系统优先于通用审美。方向仍模糊且存在多个实质选择时，先与用户收敛一个方向。

**完成标准：** 模式唯一；受众、页面任务、主要动作、设计来源、必须保留项和可改变项均已明确。若只是照稿实现，已停止本流程并路由到 `cs-feat`。

## 2. 锁定设计契约

用一句 Design Read 说明：为谁设计什么界面，以什么气质服务什么任务。随后锁定一份短契约：

- 信息层级和主要阅读路径。
- 字体气质、字号层级和正文宽度。
- 主色、中性色与最多一个强调色；现有品牌色不被静默替换。
- 间距、网格、圆角、边框、阴影和图像处理规则。
- 动效强度及其用途：层级、反馈、叙事或状态变化。
- 桌面、窄屏和触控环境中的重排原则。

选择应来自受众、内容、品牌和使用频率。运营工具偏扫描与重复操作；营销页偏叙事与转化；作品集偏作品本身；受监管界面优先信任、可读性和可访问性。

**完成标准：** 契约足以让不同页面保持同一设计语言，每项选择都能追溯到用户目标或现有约束。

## 3. 组成界面

先排内容和任务，再做表面风格。逐屏或逐区块明确：目的、内容优先级、布局骨架、主要动作、视觉资产、交互和响应式变化。

应用以下设计纪律：

- 首屏在初始视口内说清对象、价值和主要动作，并露出下一段内容线索。
- 同一页面避免连续复用相同区块骨架；用尺度、密度、对齐和图像比例建立节奏。
- 卡片只表达独立对象或真实层级；页面分区使用留白、网格或全宽色带。
- 文字、图像和控件均有稳定容器，最长文案和动态内容不会挤坏布局。
- 真实产品、人物、场所或作品是主体时，让它在首屏可见且可辨认。
- 新英雄图、产品图、场景图、纹理或逐区块参考图确有必要时，在设计产物中写明用途、构图和约束。

对应用界面补齐正常、悬停、焦点、按下、选中、禁用、加载、空、错误和成功状态；对内容页面补齐导航、链接、表单、媒体失败和长内容状态。每个多列或高差异布局都要给出窄屏重排，不把“响应式”留给实现阶段猜测。

**完成标准：** 每个屏幕或区块都有明确任务和布局；关键状态、窄屏顺序和所需资产没有空缺。

## 4. 反默认审校

审校针对结果，不机械套风格：

- 层级一眼可读，主要动作与次要动作不争抢。
- 字体、颜色、圆角、图标、阴影和图像调性保持一致。
- 没有用三等分卡片、重复左右分栏、无意义标签或假数据填补空间。
- 渐变、玻璃、纹理、动效和不对称都有信息或品牌作用。
- 可见文案具体可信；名称、数字、评价和产品画面不伪装成真实证据。
- 正文、控件、焦点和图上文字具备足够对比；颜色不是唯一状态信号。
- 触控目标、键盘路径、减少动效和媒体裁切均可成立。
- 现有界面演进没有静默改变路由、导航名称、表单字段、品牌标志、法律文本或分析钩子。

发现问题时回到对应区块修正，不用新增装饰掩盖结构问题。

**完成标准：** 所有可见屏幕和必要状态均通过契约、可用性、可访问性和一致性审校；任何保留风险都具体定位到屏幕与条件。

## 5. 交付设计

按用户需要交付 Figma 变更、视觉稿或精简设计规格。规格只保留实现所需信息：Design Read、设计契约、屏幕/区块结构、状态、响应式规则、资产和已批准的改动边界。

实现是后续独立任务，交给 `cs-feat`；实现阶段以本次设计产物为权威输入，不重新调用本技能自由发挥。

**完成标准：** 设计产物可以被实现者直接执行，未知项已显式标注，没有混入页面代码、依赖迁移或无关设计百科。
