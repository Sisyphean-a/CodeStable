# 规格化

把分散但已经确认的输入折叠成一个实施契约；不重新访谈，不补做决定。

开始前，只读[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”小节，并按该顺序取得相关当前态。来源是本地决策地图时，在读取前查看[本地地图格式](../cs-wayfinder/references/local-map.md)；输入来自本地规划面时，在首次写入前读取[交付面格式](../cs-to-tickets/references/delivery-surface.md)。

## 规格契约

规格包含问题、目的地、用户可观察行为、实现决定、测试决定、验收标准、范围外和来源。行为与验收描述结果，不写容易过时的操作步骤；决定链接唯一完整来源，不复制探索过程。

规格属于交付工作状态，不进入 `.codestable`。优先写入用户指定位置或来源规划面；来源是本地决策地图时写入该地图的 `delivery/spec.md`，没有规划面时使用 `.delivery/<name>/spec.md`。

## 步骤

1. **定源。** 确认本次规格的来源、范围和权威顺序；来源是地图时读取地图及其覆盖面链接的完整已解决决定。地图仍有打开决策项、迷雾、失效链接或冲突时，返回具体缺口并停止。**完成条件：每条来源都可达，范围内没有需要本技能猜测的未决事项。**
2. **定锚。** 按范围读取当前代码，识别现有公开边界、可复用约定和最高稳定测试接缝；只恢复实现约束，不借机选择新方案。**完成条件：规格能区分现状、期望变化和必须保持的契约。**
3. **折叠。** 按目的地合并重复结论，把每项用户行为、实现决定和范围边界链接到地图决定、当前态或代码依据；来源冲突时按权威顺序处理，无法处理则停止。**完成条件：一个含义只有一个陈述，每个范围内结论都有来源。**
4. **发布。** 在规划面写一份规格；验收标准逐条可观察、可独立判断，测试决定指向行为接缝，范围外保留理由。**完成条件：实现者只读规格及其指针即可开始拆分工单，无需重建讨论。**
5. **反查。** 从每条验收标准反向检查目的地、覆盖面、约束和来源决定。**完成条件：没有遗漏、范围蔓延、无来源要求或仍需裁决的措辞。**

## 完成条件

规划面中只有一份现行规格，覆盖全部已确认目标并保留来源指针；返回规格位置，并提示用户显式调用 `cs-to-tickets`，本次不拆工单或修改代码。
