# 项目解释

从当前项目证据恢复目标能力的真实形状，让用户既能看懂结论，也能继续定位代码。默认回答问题；图、树、伪代码、diff 和 HTML 是按问题选择的展示方式，不是独立流程。

## 步骤

1. **定界。** 把请求收敛成要解释的能力、接口、模块、符号或变化，明确用户关心的是当前行为、设计意图还是两者。**完成条件：主问题及解释边界明确。**
2. **取证。** 从真实入口定位关键符号、调用前后、数据来源、分支、失败路径、结果影响和测试；按项目规则读取直接相关的当前态，需要解释原因时才检索历史。不得只凭文件名、注释或旧文档推断实现。**完成条件：每项关键结论都有代码、测试、配置或已确认决定可定位。**
3. **还原。** 按实际执行顺序组织证据，区分：
   - `当前行为`：代码或测试直接证明；
   - `已确认意图`：项目当前态或用户决定直接证明；
   - `推测`：证据不足但有助理解，必须显式标记。
   **完成条件：入口、关键转换、主要分支、输出或副作用已闭合，未知项没有伪装成事实。**
4. **表达。** 先给直接答案，再选择最小的表达形状：短流程用编号步骤，运行路径用调用树，UI 用组件树，控制流或数据流用 Mermaid，算法用伪代码，现有形状的变化用 diff，文件职责用浅文件树；普通文字更清楚时不强行画图。每个视图只回答一个问题，并在节点或紧邻图注中绑定仓库路径与符号。**完成条件：用户无需自行拼接分散证据即可复述关键关系。**

## HTML 分支

仅当跨视图比较、复杂布局或交互能明显降低理解成本时创建 HTML：

- 只创建一个 `.tmp/cs-explain-<topic>.html`，CSS 与必要脚本内联，文件可直接打开。
- 使用真实项目标签和数据；项目相关内容沿用产品已有视觉语言，桌面与窄屏均可读。
- 生成后用默认浏览器打开并确认可访问；聊天只说明结论和文件路径，不重复整份展示。
- HTML 是本轮临时解释，不写入业务代码、项目当前态或长期读者文档。

## 完成条件

解释直接回答主问题；当前行为、已确认意图和推测已分开；入口、调用前后、分支、结果与设计原因按请求覆盖且可定位；展示没有无关节点；临时文件只位于 `.tmp/`，项目文件保持不变。
