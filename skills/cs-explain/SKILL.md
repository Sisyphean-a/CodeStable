# 项目讲解

以当前项目为证据即时回答，解释当前行为与意图；视觉表达需要时，临时产物固定落在 `.tmp/`，业务代码与长期文档保持不变。用户要通过带读和练习掌握实现时由 `cs-learn` 处理；要求把结果保存为供人阅读的流程文档时由 `cs-docs` 处理。

1. **定点。** 从用户给出的能力、接口、模块或符号出发，使用最窄的项目索引、代码入口和直接调用关系确定它负责什么、由谁触发。**完成条件：目标已落到一个可定位的职责和真实入口，不靠名称猜测。**
2. **追踪。** 沿问题相关方向查清上游输入、改变心智模型的处理节点、分支条件、状态或副作用以及下游结果；代码可直接取得的局部实现只作为证据，不展开成函数清单。**完成条件：用户所问的前因、关键路径和后果均有当前代码或有效项目资料支撑。**
3. **讲清。** 先给一句话全貌，再按问题选择 `最小视图`：信息简单时用短文字或列表，关系需要形状时用下列形式回答具体问题，并附上足以继续调查的代码锚点。
   - 逻辑或算法：伪代码；
   - 运行路径：调用树；
   - UI、模块或文件职责：组件树或浅文件树；
   - 时序、数据流或分支：Mermaid 的 `sequenceDiagram` 或 `flowchart`；
   - 变更前后：`diff`；
   - 大段新增代码、所有权或顺序容易被省略上下文遮住，或用户需要可复制目标形状：完整代码块。
   一张图只回答一个问题，图已表达的关系不再用正文复述；默认跳过冗长前言，文字保持短而具体。分别标明当前行为、已确认意图和推测；需要解释“为什么”时才按[项目记忆模型](../cs-domain/references/memory-model.md)的检索契约读取少量当前态、历史或决定，找不到依据就明确未知。**完成条件：读者无需理解函数实现也能复述主流程，并知道从哪里继续阅读。**

当用户要求可视化，或 UI 布局、状态对比、复杂概念用 Mermaid 仍不清楚时，使用一个聚焦的 HTML 图示、信息图或短幻灯片作为本轮解释产物：使用真实标签和数据，沿用目标产品的颜色、字体、间距与组件，适配桌面和窄屏；文件放在 `.tmp/show-me-<topic>.html`，生成后打开给用户。临时解释产物归属 `.tmp/`，源码、读者文档和项目当前态保持不变。

## 完成条件

回答已直接解决用户的理解问题，所有确定关系均可定位，意图与推测没有混写；没有写入代码、项目记忆或读者文档。
