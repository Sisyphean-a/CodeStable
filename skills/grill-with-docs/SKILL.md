# 带台账访谈

运行一次 `/grilling` session；只有涉及领域语言、稳定规则或语义所有权时，才使用 `/domain-modeling` 收敛。

## 工作台账

开始时按[项目记忆模型](../cs-domain/references/memory-model.md)的“工作状态”，恢复用户指定的旧台账，或以当前 `PI_SESSION_ID` 创建 `.tmp/grill-with-docs/<session-id>.md`。台账只维护目标与约束、当前问题与下一步、每个关联分支的当前有效结论、未决项与硬依赖，以及必要证据锚点。

每次用户回答后、每轮代码探索取得证据后，先覆盖更新整份台账再继续；结论不变时也刷新问题游标、下一步和证据，被替代内容从当前结论移除。原始问答、代码正文和工具输出留在 Pi 会话。**完成条件：只读台账即可准确恢复下一问题、有效结论及其依赖。**

## 访谈

按 `/grilling` 一次解决一个问题。依赖闭合、结论无冲突且证据可定位的关联分支在台账中标为闭合；跨分支结论使其失效时重新打开。整体确认前，访谈状态只落在 Pi 会话和台账。**完成条件：每个设计分支都已闭合或明确范围外，组合方案没有未决依赖或冲突。**

## 落盘

从台账生成完整方案摘要并等待用户整体确认；用户指出缺口时更新台账并继续访谈。整体确认后，把整轮方案作为一个变化单元交给 `/cs-domain` 一次归类当前态并裁决历史或 ADR。落盘和查重完成后删除台账；失败或冲突时保留台账，重试由 `cs-domain` 从现状补齐。**完成条件：最终结论只有一个权威归属，逐轮问答和局部纠正没有进入项目记忆，临时状态已清理。**
