# 对抗审查

以只读批评者身份审查最终改动；同一审查运行不实施修复。

开始定界前，只读[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”小节，并按该顺序取得判断所需的最少当前态。

## 步骤

1. **定界。** 确认准确代码差异、用户目标、现行契约和适用的仓库标准，只读改动代码及相关调用路径。**完成条件：每个改动文件和目标都有明确范围或明确排除。**
2. **双轴攻击。** **标准轴**核对仓库规则、正确性、回归、安全与数据风险、性能、维护性和测试缺口；**需求轴**从目标的触发条件攻击遗漏、部分实现、范围蔓延和看似实现但结果错误的要求。把实现摘要当作待证声明，沿调用或数据边界核对真实行为。**完成条件：每项改动和每条目标都已在对应轴上判断。**
3. **核实。** 用代码证据或聚焦的无副作用检查复现候选发现项；需求轴引用用户目标或直接来源，标准轴引用仓库规则或具体工程后果。**完成条件：每条发现项都有触发条件、依据和具体影响；每个通过项都有可复核证据。**
4. **报告。** 分标准轴和需求轴报告，各自按严重度排列，每条给精确位置和后果，随后列假设、测试缺口和残余风险。**完成条件：作者无需重建审查即可行动；无发现时明确说明。**

差异新增、移动或删除模块 interface、依赖装配、业务编排、seam 或测试面时，才读[模块深度](../cs-refactor/references/module-depth.md)，检查 shallow 转发层、泄漏的调用者知识、假想 seam 和内部测试耦合。**该分支完成条件：每个新边界都有具体 leverage、locality 或独立变化依据。**

只有命中高风险条件时才读[高风险分支](references/high-risk.md)，并核验授权、恢复、专项验证和独立性。高风险门禁必须在最终差异冻结后，由用户启动的独立 Pi 会话或人工审查执行；本技能只执行审查，不接管实现流程。

## 完成条件

范围内代码差异、用户目标及受影响契约全部审过，发现项有证据和优先级。除非结论越过记忆门槛，否则不创建长期审查报告。
