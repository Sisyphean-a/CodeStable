# 对抗审查

以只读批评者身份审查最终改动；同一审查运行不实施修复。

开始定界前，只读[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”小节，并按该顺序取得判断所需的最少当前态。

## 步骤

1. **定界。** 确认准确代码差异与预期行为，只读改动代码和相关调用路径。**完成条件：每个改动文件都明确在范围内或明确排除。**
2. **攻击。** 检查正确性、回归、安全与数据风险、契约偏差、性能代价和有意义的测试缺口；调用或数据跨边界时追到改动行之外。**完成条件：每项改动及受影响契约都已考虑。**
3. **核实。** 用代码证据或聚焦的无副作用检查复现候选发现项，删除不影响行为、维护性、安全、性能、可测性或需求的风格意见。**完成条件：每条发现项都有触发条件和具体影响。**
4. **报告。** 发现项按严重度置顶，每条给精确位置和后果；随后列假设、测试缺口和残余风险。**完成条件：作者无需重建审查即可行动；无发现时明确说明。**

只有命中高风险条件时才读[高风险分支](references/high-risk.md)，并核验授权、恢复、专项验证和独立性；本技能是实现结束后的独立门禁，不接管实现流程。

## 完成条件

范围内代码差异及受影响契约全部审过，发现项有证据和优先级；除非结论越过记忆门槛，否则不创建长期审查报告。
