# 诊断循环

本循环只服务需要可靠解释和高价值记录的故障。目标是得到一个可信的根因，以及未来可复用的复现条件、假设变化和证据锚点。

1. **建立 red loop。** 找到一条快速、确定、能在故障上失败的命令；优先使用最接近真实公开行为的测试、请求、浏览器脚本或最小测试台。收紧时间、随机数、文件系统、网络和数据等变量。**完成条件：同一命令稳定区分故障与期望行为；无法建立时明确缺少的可观测证据。**
2. **复现并最小化。** 先用原条件复现，再逐项移除无关输入、状态和步骤，每次回到 red loop。**完成条件：最小复现仍红，必要条件与偶然条件已分开。**
3. **提出可证伪假设。** 按解释力排列少量候选，每个候选写明若为真应看到什么、若为假应看到什么。**完成条件：下一次观测能淘汰至少一个候选。**
4. **定向插桩。** 只增加能区分当前候选的日志、断言、追踪或探针；性能问题先建立基线并使用 profiler、查询计划或二分。**完成条件：证据选出能解释全部观察的根因，临时插桩位置可清理。**
5. **锁定修复。** 稳定公开测试面能表达故障时，先把 red loop 固化为回归检查，再修改根因并运行受影响回归。**完成条件：原循环转绿，根因变化能预测该结果，相关契约仍成立。**
6. **清理与交接。** 移除临时插桩和一次性测试台；向调用技能交回根因、特殊复现条件、改变的假设、残余风险和代码或测试锚点。**完成条件：记录裁决无需重放调试过程，仓库没有诊断过程产物。**
