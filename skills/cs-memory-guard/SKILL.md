# CodeStable 规范守门

修复一个已发现的局部 `.codestable` 规范冲突。它只产出局部文档修复或明确的待裁决项；项目初始化、整体迁移、记忆剪枝和语义归档分别交给 `cs-onboard`、`cs-docs-neat` 和 `cs-domain`。

## 规则来源

先读取目标文件、触发它的规则来源和项目记忆模型的“按范围加载”小节，再按命中分支披露：

- 结构或格式问题：读取“检索契约”和直接相关的当前态入口；
- 历史条目问题：再读取“历史”小节和命中的当前依据；
- 当前态或语义冲突：再读取“记忆门槛”“当前态位置”和直接相关的架构或领域页面；
- 迁移问题：再读取对应的迁移规则和旧来源。

`.codestable/attention.md`、`architecture/INDEX.md`、目标包页面和 `requirements` 页面只在定域或判断权威归属时取得；不读取无关范围、全部历史或完整旧来源。项目记忆模型是格式、权威归属和迁移边界的唯一规则源；本技能只执行，不复制这些规则。

## 步骤

1. **定域。** 确认仓库根、目标 `.codestable` 文件、最小工作区或包范围和触发它的具体规则。没有目标文件或没有可定位规则时回报 no-op、原因和未修改的范围。**完成标准：目标、范围、规则来源和允许修改的文件集合唯一确定，或已明确无动作及其原因。**
2. **分类。** 将目标归为一个状态：
   - `current-valid`：符合当前规则；
   - `legacy-valid`：旧格式被当前规则保留，或有明确版本兼容依据；
   - `deterministic-violation`：存在可证明、无损、可重复的修复；
   - `semantic-conflict`：需要推断原因、当前依据、范围、事实归属或迁移意图。
   **完成标准：只有一个状态和一个规则标识；旧格式不会仅因缺少新字段而自动变成违规。**
3. **派发。** 只有 `deterministic-violation` 适合交给可用的子代理；传入目标文件、规则来源、规则标识、允许修改范围、期望补丁和验证方式。子代理不可用时由主代理用同一输入执行一次局部修复并验证，不扩大扫描范围。`semantic-conflict` 形成交给 `cs-domain` 的待裁决项，并附目标文件、规则标识、当前证据、冲突点和待决定问题。**完成标准：修复执行者和修改边界明确，语义判断没有被伪装成机械修复。**
4. **修复。** 只修改允许的目标文件，使用确定性或已确认的迁移映射；保留历史日期、证据、原始路径和仍然有效的旧条目，不编造缺失事实，不借机重排无关文档。机械修复不新增历史记录；语义变化交给 `cs-domain` 判断当前态和留痕。**完成标准：补丁幂等、范围最小、没有丢失唯一证据或新增未经确认的事实。**
5. **验证。** 重新读取修改后的目标文件，按同一规则再次分类；如环境提供校验命令则只对目标范围运行，并执行 `git diff --check -- <允许文件>`。确认第二次运行不会产生新的补丁，且当前态入口、历史证据和替代关系仍可追踪。**完成标准：目标为 `current-valid` 或 `legacy-valid`，验证证据可定位；否则保留原文并返回未决项。**

## 子代理回报

子代理或本轮执行结束时保持紧凑回报：目标文件、规则标识、分类结果、实际补丁、验证证据和未决项；`semantic-conflict` 额外回报当前证据、冲突点和 `cs-domain` 待决定问题。完整仓库扫描、迁移报告和清理报告属于其他技能的结果。

## 完成条件

目标范围内的已发现冲突已成为可验证的 `current-valid` 或 `legacy-valid`，或已保留原文并交出带证据的 `semantic-conflict`；没有目标时已回报 no-op。修改只覆盖允许文件，唯一证据可追溯，且没有启动初始化、整体迁移、剪枝或语义归档流程。
