# 项目记忆模型

这是 CodeStable 项目记忆加载、检索与写入的唯一规则源。

## 权威顺序

冲突按下列顺序处理：

1. 当前代码和已明确确认的决定。
2. `architecture/`、`requirements/` 下的领域上下文与有效架构决定记录。
3. `history/` 和已替代架构决定记录。
4. 旧任务、审查、审计、探索与迁移文档。

旧文档描述旧行为，不足以把合理演进判成缺陷。应恢复当前态，并标记或删除陈旧材料。

## 工作状态

未闭合的讨论、探索证据和决策依赖属于工作状态。优先使用调用技能已有的规划面；只需跨上下文恢复且没有规划面时，使用仓库根 `.tmp/<mechanism>/` 下由调用技能赋予稳定身份的快照。在 Git 仓库首次写入前，先确保 `.tmp/` 已被仓库忽略规则排除；否则加入本地 `.git/info/exclude` 并用 `git check-ignore` 验证，无法保证排除时先让用户处理。工作状态维护可恢复的当前快照，由具体技能定义变化单元、格式和清理时机；它保持可丢弃且不进入 Git，也不作为源码、构建或测试依赖。

变化单元达到调用技能的完成条件、无冲突、证据可定位并经必要确认后，才能一次晋升到当前态；此前内容持续更新工作状态。原始问答和工具过程由 Pi 会话保留。

## 按范围加载

从改动路径确定 `workspace`、`package:<name>` 及其映射的 `context:<name>` 或 `shared:<name>`。任务开始只读：

1. `.codestable/attention.md`；
2. `.codestable/architecture/INDEX.md`；
3. 目标包页面和直接依赖的共享页面；
4. `requirements/CONTEXT.md` 的作用域地图与工作区条目；
5. `requirements/shared/<scope>.md` 和 `requirements/contexts/<context>.md` 中与目标直接相关的文件。

普通读者文档、架构决定记录、历史和旧证据不在默认工作集；按下列检索契约按需取得。单仓多包项目只保留一个根 `.codestable`。

## 检索契约

- 当前架构和领域规则必须能从对应范围的 `architecture/INDEX.md`、包页面或 `requirements/CONTEXT.md` 作用域地图到达；新增或移动当前态页面时同步该入口。
- 长期维护的读者文档沿用仓库已有的 README、包文档索引或当前态页面入口；没有现成入口时，以明确发布位置、标题和摘要支持搜索，不为单篇文档新建总索引。
- 架构决定记录和历史无需逐条进入当前索引。架构决定记录保留准确范围、当前规范词及必要旧称、代码锚点和相关历史，替代后指向新依据；历史保留准确范围、规范词及必要旧称、具体当前依据，并以代码路径、符号、提交或原始来源作证据。
- 查询先按范围读取当前态。只有问题询问原因、现行证据冲突或需要确认替代关系时，才用范围、规范词或旧称、当前页面路径、代码路径或符号检索少量架构决定记录和历史；证据足以解释问题后停止，不遍历全部历史。

## 当前态位置

- `architecture/INDEX.md`：范围地图、主题链接、包归属。
- `architecture/shared/<topic>.md`：一个跨包契约、不变量或共享机制。
- `architecture/packages/<package>.md`：包职责、公开边界、依赖、共享差异和代码锚点。
- `requirements/CONTEXT.md`：领域作用域地图，以及整个工作区共同使用的通用语言、稳定业务规则和不变量。
- `requirements/shared/<scope>.md`：由若干明确领域上下文共同拥有且没有单一所有者的领域语言与规则。
- `requirements/contexts/<context>.md`：一个领域边界拥有的语言与规则，并映射到实现它的一个或多个包。
- `requirements/adrs/`：存在真实替代方案且回退代价高的决定。

共享事实只在一个权威文件定义；其他范围只链接并记录本范围影响。

## 领域上下文

领域事实按语义所有权归档，而不是按当前讨论位置或代码复用范围归档：

- `workspace`：事实没有更窄的语义所有者，并约束所有相关领域上下文。
- `context:<name>`：含义由一个领域边界拥有；该边界可映射到一个或多个包。
- `shared:<name>`：相同含义由若干明确领域边界共同拥有且没有单一所有者；仅仅复用代码不构成共同拥有。

先按语义所有权判断，再看使用范围。包是实现边界，不自动成为领域边界；跨包导入类型、引用标识符或消费事件不会扩大术语作用域。同名概念在不同领域边界中含义不同时分别定义，并在跨边界讨论中使用限定名。作用域未确认前保留歧义，不把事实写入更宽范围。发现已有事实范围过宽或过窄时，把定义移动到正确的唯一文件，并从原位置链接过去。领域上下文的具体版式以[领域上下文格式](domain-context-format.md)为准。

## 记忆门槛

先确定**变化单元**：一项已经整体接受的设计变化或已实现结果，能独立说明改变了什么。同一任务或访谈内的局部确认、纠正和分支结论合并到最小可独立解释的变化单元；形成前留在工作状态。

再问：**未来人工智能若不知道这次变化的原因，会不会做出错误判断？**

- **不会：** 不写 `.codestable`。格式化、机械重命名、生成文件变化和普通样式调整通常止于 Git。
- **会：** 追加一条历史。
- **接口、模块边界、业务规则或既有假设变化：** 写历史并更新权威当前态。
- **安全、数据、不可逆操作、跨包协议或高代价取舍：** 再新增或替代架构决定记录。

若视觉变化承载无障碍、品牌、兼容等长期约束，就不再是机械改动。

## 历史

追加到 `.codestable/history/YYYY-MM.md`，不创建任务目录：

```md
- 日期 · [功能|缺陷|重构|演进] 一句话结果。范围：workspace|package:<name>|context:<name>|shared:<name>（多个时逐项列出）
  原因：为什么现在改变。
  当前依据：更新过的架构、领域上下文或架构决定记录；没有则写“无”。
  证据：提交、代码路径或原始历史链接。
```

历史是 Git 的语义索引：保留能减少未来误判或昂贵考证的重要变化结果、原因、当前依据和原始证据，Git 保留完整过程与差异。历史只概括规则如何变化及为何变化，规则正文由当前态唯一维护；条目可按判断价值合并、压缩或删除，不因年代久远或 Git 已有证据而自动删除。常规命令、通过结果、文件清单、只说明完成的里程碑和审查过程由持续集成、Git 与代码保留。

## 架构决定记录

架构决定记录写明背景、决定、真实备选、后果、范围、代码锚点和相关历史。状态使用 `accepted` 或 `superseded`，替代时设置 `superseded-by`，不得静默删除。
