# 前端视觉生成

把图像当作前端结构的一部分，而不是装饰。页面视觉契约由 `cs-ui-design` 负责，页面代码由 `cs-feat` 负责；本技能只负责区块参考稿或页面媒体资产的方向、生成和验收。已有图片只需压缩时不进入本流程。

## 1. 定域

先读用户 brief 和已确认的页面视觉契约；契约仍模糊时交给 `cs-ui-design`，只有一个视觉选择未决时可先用 `cs-brainstorm` 收敛，不在生成阶段替用户暗中选择。为每个待生成项选择一种模式：

- **区块参考稿**：完整表现一个网页区块的布局、层级、短文案、CTA、组件和图像处理，供开发者照图实现。
- **媒体资产**：供页面直接使用的英雄图、产品图、场景图或纹理；不烘焙 UI 文字，并明确叠字安全区与裁切方向。

确认页面类型、受众、主要转化动作，以及每张图承担的工作：吸引、说明、展示产品、建立信任或收束行动。再确认区块数量、横向比例、文字安全区、裁切方向和现有品牌资产。

**完成标准：** 每个待生成项都有唯一模式、区块归属、视觉任务和展示约束。

## 2. 锁定视觉契约

在生成第一张图前，做一份短契约，并在所有图片中复用：

- 一套色彩：主色、辅助色、强调色和中性色。强调色最多一个。
- 一种字体气质和层级逻辑。区块参考稿只放能表达层级的短文案；媒体资产不烘焙 UI 文字。
- 一种影像处理方式：真实摄影、产品特写、编辑感裁切、材质纹理或抽象结构，按 brief 选择。
- 一套材质、边角、光线和对比度规则。
- 一个英雄区尺度：巨幅宣言、中型编辑或微型极简，按品牌气质明确选择。
- 一个叙事概念和一个只出现一次的记忆点。

构图要有变化，但品牌契约不能变。多区块页面至少使用三种构图锚点；同一锚点不连续超过两次。默认避开紫蓝 AI 渐变、无意义光球、堆叠假卡片、虚假 KPI 和纯模板式左右分栏，除非 brief 明确要求。

**完成标准：** 契约能约束整组图片，并且没有为了制造变化而改变品牌世界。

## 3. 按区块拆图

图片数量严格等于区块数量：一节一张独立横图，不做长页面截图、拼贴或把多个区块塞进一张图。

数量不明确时使用以下默认值：

| 请求 | 图片数 |
| --- | ---: |
| hero | 1 |
| landing page / marketing site | 6 |
| product page | 6 |
| full website | 8 |
| portfolio | 6 |

先列出区块计划，再生成。每行至少包含：区块名与转化任务、输出模式、比例、构图锚点、背景方式、主体、文字安全区和 CTA 层级。区块参考稿需要形成 `吸引 -> 证明 -> 说明 -> 行动` 的可读路径；媒体资产只承担所在区块的局部任务。非极简多区块页面应至少有一次全幅或氛围图；极简、Swiss 或纯文字 brief 可以保持克制。区块之间可以有大、中、小节奏，但不能靠重复卡片填满画布。

**完成标准：** 区块计划的行数等于目标图片数，每行都能直接转成一次独立生成请求。

## 4. 生成与落盘

每次请求都带上以下信息：

1. 区块任务和受众，不写成泛泛的 moodboard。
2. 画布比例与主体位置，明确可供前端叠字或裁切的安全区。
3. 视觉契约中的色彩、材质、光线和影像处理。
4. 本区块特有的构图、尺度和密度；不要复制上一张的布局。
5. 实现提示：层级清楚、留白可用、主体边界明确、移动端裁切仍能成立。

优先使用环境中可用的图像生成工具。一次只能生成一张时，按计划顺序生成，并在响应中标明 `第 X/N 张：区块名`，直到数量完整。图像生成工具不可用时，使用用户提供或明确允许的真实来源；两者都没有时留下清楚的占位需求，不把手绘 SVG 或假截图伪装成成品。

外部生成图、下载图和中间截图先放仓库根 `.tmp/`。只有用户明确要求把它们接入业务资源时，才移动到项目约定的静态资源目录，并同步检查引用。

**完成标准：** 每张图已单独生成或被明确标记为待补资产，文件位置和区块归属可追溯，没有伪造成功。

## 5. 验收

交付前逐项检查：

- 数量准确：每个区块一张，全部为横向画布。
- 统一性成立：色彩、字体气质、材质、光线、裁切和 CTA 视觉语言属于同一品牌。
- 变化成立：构图、主体尺度、背景方式和密度有节奏，未连续复制同一模板。
- 可实现：区块参考稿的布局、层级、CTA、留白和主体边界足够明确；媒体资产的安全区与裁切约束足够明确。
- 转化完整：区块参考稿能读出吸引、证明和行动，主要 CTA 始终最清楚，次要 CTA 不与之争夺层级。
- 可用性成立：桌面比例与移动裁切都不损失主体；文字和按钮不会被图像抢掉对比度。
- 资源可用：格式、尺寸、透明度和引用正确；临时文件没有进入源码、构建或测试依赖。

**完成标准：** 所有检查通过，或每个未通过项都被明确标为残余风险并交给主技能处理；不能只返回一张代表图或一份抽象方向说明。

## 与其他技能的边界

- `cs-brainstorm`：只有一个页面视觉选择未决时，发散并收敛方向。
- `cs-ui-design`：创建或改变页面的视觉契约、结构、状态和响应式规则。
- `cs-feat`：按已确认设计实现完整页面，包括信息架构、布局、交互、状态和代码。
- `imagegen-frontend-web`：需要新视觉资产时，负责区块拆分、图像方向、生成请求和整组验收。

同一任务只让一个技能拥有主流程。本技能作为 `cs-ui-design` 的视觉资产分支进入，完成后把图片和约束交回设计任务；已有设计下实现页面时不调用本技能，除非设计明确留下待生成资产。
