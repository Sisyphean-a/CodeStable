# 代码减法

减少代码承担的维护责任，以最小必要复杂度保留完整、稳定、正确的行为。成功看每次修改需要理解的系统是否更小，行数只是辅助证据。

## 边界

只处理请求范围内的人为复杂度；正常运行不是保留的充分理由，必要性才是。业务规则、事务、安全、数据完整性、幂等和故障恢复有真实职责时保留；单一实现也可能承担隔离、测试替换或外部系统边界。

主动撤销仍有效的能力或外部契约属于功能变更，修复错误属于缺陷；编辑前明确归类并取得相应授权。日常功能和一般重构只在触及范围内控制复杂度，不自动扩张为本技能的专项清理。

开始定域前，只读[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”小节，并按该顺序取得范围当前态。

## 步骤

1. **定域。** 圈定请求范围、真实入口与依赖边界，列出需保留的输出、错误、顺序、副作用、性能承诺和必要保护。选择能反映当前负担的比较项：认知范围、修改范围、无价值转发深度或重复规则维护点，记录具体路径或数量。**完成条件：精简目标、不变量和前后比较基线可核对。**
2. **证明。** 从下方候选中调查实际职责、消费者和删除影响；核查公开导出、配置装配、动态调用、运行时副作用及历史兼容要求。逐项回答：是否有独立职责，移除会失去什么能力或保护，维护收益是否超过理解成本。引用搜索和单一实现数量仅是线索；证据不足时继续调查，仍无法确认的候选保留并说明缺口。**完成条件：每个拟改候选都有必要性结论、依赖证据和验证方法；仅实施已证明可安全精简的项。**
3. **减法。** 优先删除不必要实现 → 复用已有能力 → 合并同一规则 → 内联无价值转发 → 使用现有成熟工具 → 确有必要才建立新抽象；偏离时说明具体收益。采用可独立验证和撤回的小步，同步清理失效导出、注册、配置、依赖和旧实现专属测试；保留契约测试，覆盖不足时先补最小行为测试。不同职责保持各自边界，新增依赖也计入维护成本。**完成条件：多余实现或概念实际消失，复杂度没有搬到新包装、巨型模块、隐式依赖或隐藏副作用中。**
4. **验证。** 运行与风险匹配的行为等价和受影响回归检查，跨边界时覆盖真实装配；核对不变量，并以同一口径比较定域基线。失败时定位根因，未验证部分明确保留为待验证。**完成条件：证据证明契约及必要保护未变，至少一项维护负担降低，局部修改范围未扩大，可读性和可测试性未削弱。**
5. **记忆裁决。** 机械清理通常无需文档；真实模块边界或稳定依赖变化越过记忆门槛时，才读项目记忆模型的“记忆门槛”和对应写入小节，更新唯一当前态及必要历史。**完成条件：明确无需文档，或长期边界变化已进入唯一权威位置。**

## 减法候选

- 无实际消费者的代码、配置、过期兼容分支和被替代的旧路径。
- 不承担独立边界的单实现接口、只透传参数的中间层。
- 无契约必要性的 DTO 转换、数据包装和重复校验。
- 同一语义规则的重复实现，或重复维护框架已有能力的自建设施。

涉及拆合模块、移除抽象、移动依赖、业务编排或测试面时，在减法前读[模块深度](../cs-refactor/references/module-depth.md)，以删除测试、seam、locality 和公开测试面检查保留真实边界。

触及安全、持久化数据、生产、不可逆影响或核心协议时，在风险动作前读[高风险分支](../cs-code-review/references/high-risk.md)。

## 完成条件

范围内候选均已裁决；有证据的减法实际落地，契约等价验证通过，维护负担下降。简报交代删去了什么、为何可删、前后收益和验证缺口；没有安全候选时明确报告，不以凑删行数制造改动。不创建专项扫描、设计或常规审查文档。
