# 功能

直接交付可观察结果，不创建并行规划流程。

## 边界

本技能处理有意行为变化，也负责按已确认的 Figma、设计稿或固定设计系统实现界面。用户当前只想把模糊意图变清楚时属于 `cs-goal`；用户要独立的视觉方案时属于 `cs-ui-design`；用户要可运行结果并把方案与可逆设计决定委托给 Agent 时，本技能直接进入目标模式。期望行为不变的内部结构调整属于重构；现有行为违反既定契约属于缺陷。证据改变分类时，编辑前重新归类。

开始定域前，只读[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”小节，并按该顺序取得相关当前态。

## 输入模式

- **契约模式**：期望行为或现行设计已经明确，直接按契约交付。
- **目标模式**：用户只给出期望变化并委托方案判断；在工作上下文中形成短小的 Goal Read，包括用户处境、期望变化、产品身份与主要对象、核心场景、体验不变量和反目标，不创建目标文档或并行设计流程。

目标模式只在不同解释会形成实质不同的产品身份，或决定涉及不可逆影响与高风险时提问；问题给出候选解释和推荐。可逆的技术、布局和交互细节由 Agent 依据当前项目自行决定。每项主要行为和可见细节都应能追溯到 Goal Read 或现行约定；无法追溯、形成竞争性产品中心的内容应删除。用户指出局部“别扭”时，先校正产生它的上层假设，再检查同一假设影响的其他细节。**完成条件：一个连贯解释足以指导实现，没有被静默掩盖的产品身份冲突。**

## 步骤

1. **定域。** 从可能改动路径确定 `workspace` 或 `package:<name>`，读取相关当前态和代码；目标模式同时完成 Goal Read。**完成条件：现有契约或目标主线、期望结果和受影响边界明确。**
2. **实现。** 用最小完整改动交付结果，设计沿用仓库现有约定，除非功能本身改变约定。稳定公开测试面能低成本证明新行为时，以一个失败检查和最小实现组成垂直切片；小型直接改动沿用最窄的聚焦检查。**完成条件：真实路径中的所有请求行为及相关错误/空状态都存在，整体结果没有偏离 Goal Read。**
3. **验证。** 运行能证明可观察结果和受影响契约的聚焦检查；跨边界时扩大到集成或回归。目标模式还要以核心场景和一个反场景检查产品重心。**完成条件：新证据覆盖全部必需路径，没有已知漏测或主线冲突。**
4. **记忆裁决。** 先判断未来是否会因不知道原因而误判；越过门槛时才读项目记忆模型的“记忆门槛”和对应写入小节。Goal Read 只有经用户确认成为长期项目或包主线时才进入当前态，并原地合并或替代现行规则，不追加局部反馈。**完成条件：明确无需文档，或已完成必要的历史与当前态更新。**

只有功能会新增或改变模块 interface、依赖装配、业务编排或跨模块数据流时，才在实现前读[模块深度](../cs-refactor/references/module-depth.md)；普通局部行为变化跳过。**该分支完成条件：新增边界通过参考中的删除测试、seam、locality 和测试面检查。**

只有触及安全、持久化数据、生产操作、不可逆外部影响或核心跨包协议时，才在风险动作前读[高风险分支](../cs-code-review/references/high-risk.md)。

## 完成条件

可观察结果有效，必要验证通过，高风险义务已结清，项目当前态不与实现冲突；不创建功能计划、检查清单、质量报告、验收或常规审查产物。
