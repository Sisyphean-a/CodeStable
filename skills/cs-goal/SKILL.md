# 目标收敛

把模糊想法或偏离感收敛为一份已确认的产品主线；本技能拥有“要成为什么”，不拥有解决方案、界面设计或代码实现。

## 边界

选择一种模式：

- **从零成形**：尚无稳定产品身份，从模糊想法识别用户处境、期望变化和产品中心。
- **方向校准**：已有产品或页面整体感觉不对，从当前结果反推它实际在优化什么，再定位与用户目标冲突的上层假设。

用户要的是可运行结果时由 `cs-feat` 直接承接目标型委托；用户要视觉方案时由 `cs-ui-design` 负责。已有产品主线明确且实现只是违反它时，说明冲突并停止收敛，后续属于缺陷修复。

现有项目先按[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”取得相关当前态和真实产品；可由代码、页面、文档或环境查明的事实由 Agent 查明，不要求用户复述。**完成条件：模式唯一，当前事实、用户判断和 Agent 推测已分开。**

## 候选解释

从零成形时，给出少量产品身份实质不同的解释；方向校准时，先给出“当前产品实际像什么、用户可能希望它成为什么”的差异诊断。每种解释只讨论用户变化、主要对象、体验重心和失败方向，并给出推荐，不展开功能表、技术选型或布局方案。

让用户通过“像 / 不像、哪个更接近、明确不要什么”校准解释；只询问会改变产品身份的问题，不把可逆细节变成用户作业。用户否定具体细节时，寻找产生该细节的上层假设，并检查同一假设影响的其他判断。**完成条件：只剩一个产品身份，或唯一未决的身份冲突已显式可回答。**

## 场景压测

用一段核心使用场景说明用户从什么处境进入、完成什么变化、什么是体验中心；再用一个边界或反场景检验产品是否会滑向相邻但错误的身份。场景只验证目标，不提前决定界面、模块或交付步骤。**完成条件：核心场景、体验中心和反目标互不冲突，用户能根据场景判断方向是否正确。**

## 产品主线

把结论压缩为一张短卡：

- 目标用户与发生时刻；
- 期望变化；
- 产品身份与主要对象；
- 核心场景；
- 体验不变量；
- 反目标；
- 仍未确认但不阻碍主线的边界。

产品主线只保留能独立改变未来判断的原则；可由现有原则推出的反馈不重复记录，新结论优先合并、收窄或替代旧规则。**完成条件：另一个设计者或实现者无需重放对话，就能判断一个候选细节是否偏离主线。**

## 确认与记忆

等待用户整体确认产品主线。未闭合内容只留在会话或用户明确保存的临时检查点；不把候选解释和逐轮反馈写进项目当前态。

现有项目中，只有用户同时确认该主线具有长期的项目、包或领域范围时，才按[项目记忆模型](../cs-domain/references/memory-model.md)的“记忆门槛”和对应写入小节更新最窄的唯一当前态；现行规则原地合并或替代，必要原因进入历史而不进入默认工作集。一次性任务目标或仍属偏好的判断不落盘。**完成条件：产品主线已确认；跨对话价值明确时已有唯一权威归属，否则已明确止于当前对话。**

## 完成条件

产品身份、用户变化、核心场景、体验不变量和反目标已形成一致主线，未决边界仍可见；没有产出技术方案、UI 规格、功能计划或代码，项目记忆没有吸收过程性反馈。
