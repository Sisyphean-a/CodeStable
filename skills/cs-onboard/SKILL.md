# 项目记忆脚手架

建立一个可按范围加载的小型项目记忆。已有目标结构的日常清理由 `cs-docs-neat` 负责。

## 目标结构

```text
.codestable/
├── attention.md
├── architecture/
│   ├── INDEX.md
│   ├── shared/
│   └── packages/
├── requirements/
│   ├── CONTEXT.md
│   └── adrs/
└── history/
```

单仓多包项目只使用一个根目录，并以 `scope: workspace` 或 `scope: package:<name>` 标记事实。

开始检查前，只读[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”和“当前态位置”小节。

## 步骤

1. **检查。** 找出仓库根、工作区或包、公开边界、现有项目规则和 `.codestable` 内容。**完成条件：拓扑及搭建或迁移模式明确。**
2. **搭建。** 创建目标目录，写简短注意力规则、带代码锚点和包归属的架构索引，以及只含已验证术语、稳定规则和不变量的 `CONTEXT.md`；有证据时才建包页面或共享页面。**完成条件：新会话无需扫描仓库即可定位范围。**
3. **迁移分支。** 只有存在旧任务、审查、探索或生成式运行资料时，才读[旧记忆迁移](references/migration.md)，按主题处理。**完成条件：每个已迁移事实有当前权威归属，未迁移来源仍原样保留。**
4. **检索验证。** 用一个工作区任务和每个已表示包按范围加载。**完成条件：不遍历任务目录或无关包即可找到当前设计、原因和替代历史。**
5. **剪枝。** 唯一证据已表示或可从 Git 恢复后，删除旧运行程序、门禁、模板和过程目录。**完成条件：不存在新旧双轨。**

## 完成条件

目标树是唯一默认入口，当前态与代码一致，共享事实只有一个权威归属，旧证据可追溯，项目内未安装流程运行程序。
