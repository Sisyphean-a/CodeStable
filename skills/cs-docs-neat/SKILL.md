# 剪枝

结果必须是更短、更准确的默认工作集。首次初始化或整体迁移属于 `cs-onboard`。

开始定域前，只读[项目记忆模型](../cs-domain/references/memory-model.md)的“按范围加载”和“检索契约”小节，并按该顺序取得当前工作集。

## 步骤

1. **定域。** 从改动路径或用户目标确定 `workspace` 或 `package:<name>`，只读该范围的注意力规则、当前态、直接共享依赖、读者文档入口及其当前候选、按检索契约命中的历史和活动旧单元。**完成条件：无关包和未命中历史被排除。**
2. **裁决。** 每份候选或历史条目只能选一项：保留当前事实、提炼进权威位置、用新依据替代旧结论、合并或压缩仍有价值的原因链、删除已吸收过程材料。**完成条件：每份候选都有唯一裁决。**
3. **执行。** 删除源材料前先写入有效结论，保留代码锚点、日期和 Git 或原始证据。**完成条件：没有唯一证据丢失。**
4. **校准。** 将保留结论与代码和已确认决定对照；旧文档只描述历史行为时恢复当前真相，只有权威证据真正冲突才询问。**完成条件：当前态不与代码冲突。**
5. **删除。** 清除已完成计划、只说明完成的里程碑、常规验证、文件清单、重复报告、当前规则副本、已吸收探索和空过程目录。**完成条件：范围内默认文件集变短，或确认没有沉积可删。**
6. **验证。** 检查孤立当前文档、陈旧代码或文档路径、共享事实复制和范围泄漏。**完成条件：当前态可从对应入口到达；长期读者文档可从既有读者入口到达，或由发布位置、标题和摘要命中；保留的历史可由代表性范围、术语或代码锚点命中并追到证据。**

候选命中历史时，才读项目记忆模型的“历史”小节；裁决要求写当前态或历史时，才读“记忆门槛”和对应的“当前态位置”或“历史”小节。

## 完成条件

范围内所有候选已处理，当前态与代码一致，当前材料可导航，历史证据可检索且可追溯，并且没有新增清理报告。
