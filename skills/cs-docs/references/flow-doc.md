# 流程文档

流程文档是用户选择长期阅读的独立读者材料，不是项目当前态、工作状态、历史或日常开发记录。只有用户明确要求保存、编写或更新流程说明时才维护；其他技能不因代码变化自动创建、读取或同步它。

## 选择

围绕一个稳定的读者问题记录端到端流程、调用时序、数据流、模块职责或关键分支。一次回答即可满足、实现仍频繁变化或只能罗列函数时，保持即时讲解，不新增文档；已有同主题文档时原地更新。**完成条件：该流程有重复阅读价值，并且只有一个现行读者文档归属。**

## 核实

从当前代码确认入口、输入来源、关键节点、分支条件、状态或副作用、结果去向和代码锚点；锚点使用仓库相对路径加符号，如 `src/order/service.ts#OrderService.create`。开发者意图只采用用户确认、有效当前态、历史或决定记录。分别表达当前行为、已确认意图和仍未确认之处。**完成条件：图中每条确定关系都有依据，代码形状没有被冒充为开发者意图，关键节点可从锚点直接定位。**

## 压缩

图承担结构，文字只补目的、非显然意图、重要边界、未确认项和继续阅读的代码锚点：

- 生命周期、请求响应、等待和异步事件使用 `sequenceDiagram`。
- 结构、数据流、职责和条件分支使用 `flowchart TD`；短而简单的横向关系才使用 `flowchart LR`。
- 一张图只回答一个问题；总览与局部、正常与异常确需独立阅读时使用不同 Mermaid 代码块。
- 节点使用业务或机制名称，必要代码原名放在图后；合并不改变心智模型的辅助调用。
- 省略签名、类型和可从单次代码查找取得的局部实现；正文不复述图中已有关系。

**完成条件：读者主要看图即可复述流程，文字只保留图无法可靠承载的信息。**

## 发布与维护

沿用仓库现有读者文档位置和入口；没有现成位置时使用 `docs/flows/<topic>.md`，以明确标题和摘要支持发现，不把它加入 AI 默认工作集。Git 仓库写入当前 commit，并说明相关代码锚点是否含未提交改动；没有 Git 时标记“当前工作树（无 Git commit）”。核实基线只说明文档对应的代码状态，不触发后续同步。使用稳定语义和精确代码锚点降低漂移，不复制项目当前态；Git 负责修改过程。写后检查 Mermaid 基础语法、链接、锚点及与当前代码的一致性。**完成条件：目标读者能找到并独立阅读文档，能判断文档的核实基线及工作树状态，现有同主题材料没有重复或冲突，后续维护只需在用户要求时原地重新核实。**

建议骨架：

````md

{这条流程解决什么问题。}
````
