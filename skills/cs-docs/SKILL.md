# 读者文档

围绕一个明确读者结果写作；项目当前态由记忆技能另行维护。

## 步骤

1. **读者。** 固定受众、要完成的任务或要理解的问题、前置知识、事实源和发布位置。**完成条件：文档只有一个读者结果和清晰边界。**
2. **核实。** 读取当前实现、公开契约和相邻文档，以代码和已确认决定消解冲突。**完成条件：每个待写行为都有权威来源。**
3. **写作。** 沿用现有信息架构和术语，围绕读者结果组织内容；细节链接到权威位置而不复制，操作示例可运行。**完成条件：读者无需了解写作过程即可完成目标或建立正确心智模型。**
4. **验证。** 可行时运行示例，检查命令、符号、链接、标题和生成规则。**完成条件：没有陈旧名称或无法核实的断言。**

只有创建或移动长期维护的文档时，才读[项目记忆模型](../cs-domain/references/memory-model.md)的“检索契约”小节；沿用面向目标读者的现有 README、包文档索引或当前态入口，没有现成入口时保留明确发布位置、标题和摘要。**该分支完成条件：目标读者能从既有入口到达，或用主题标题与摘要在发布位置命中文档，且没有为单篇文档新增总索引。**

只有用户明确要求保存、编写或更新端到端流程、调用时序、数据流、模块职责或关键分支的读者文档时，才读[流程文档](references/flow-doc.md)。该材料独立于项目记忆和日常开发记录，不随普通代码改动自动维护。**该分支完成条件：图与必要文字帮助读者理解已核实流程，且没有进入 AI 默认工作集。**

只有写 API 参考时，额外穷举范围内公开端点或符号、输入、输出与错误、认证或副作用及一个有效示例。**该分支完成条件：参考与当前公开面逐项一致。**

## 完成条件

读者结果完整，事实与示例已验证，链接有效，不创建设计、构建清单或文档清理流程产物。
