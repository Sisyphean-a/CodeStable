---
name: grilling
description: 无休止地拷问用户关于计划、决策或想法。用户想压力测试他们的思考，或使用任何 “grill” 触发短语时使用。
---

无休止地访谈用户，直到达成共同理解。把问题画成一棵**设计树（design tree）**：每个决定都会分出依赖它的决定。

按**轮次（rounds）**推进这棵树。**前沿（frontier）**是所有前置条件已经解决的决定——也就是你现在无需猜测尚未得到的答案，就能提出的问题。每一轮把整个前沿一次问完：给每个问题编号，并给出你的推荐答案。然后等待用户回答，再进入下一轮。

每个问题都按下面的格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以包含多段文字和多个选项>

➡️ <你的推荐答案>
```


每一轮用户的回答都会重塑这棵树：已经解决的决定会把前沿向外推进，并解除依赖它的问题。一个问题如果依赖本轮仍未解决的另一个问题，就属于**之后的轮次**，不要在本轮提问。

查找**事实**是 agent 的工作，不是用户的工作。如果前沿问题需要环境中的事实（文件系统、工具等），派 subagent 去查，不要向用户询问本来可以自己查到的内容。不要因此阻塞：探索正在运行时，它仍是未解决的前置条件，所以只有依赖它的问题需要等待；现在先问前沿中其他问题。**决定**由用户做出——把每个决定摆给用户，等待回答。

当前沿为空时，会话完成：设计树的每个分支都走过了，没有任何内容被默默假定。在用户确认已经达成共同理解之前，不要采取行动。
