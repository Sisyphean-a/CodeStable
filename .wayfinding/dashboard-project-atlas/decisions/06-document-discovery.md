# 确定文档发现与搜索边界

## 问题

为了让不熟悉仓库结构的用户找到正确资料，dashboard v2 首版需要哪些目录、分类、筛选、搜索和排序能力，并应如何体现当前态、历史、工作状态、读者文档及权威顺序而不承诺通用全文检索系统？

## 答案

采用**权威优先目录 + 跨实体结构化搜索**。首版先让用户理解资料属于什么、是否当前有效、为什么会出现在结果中；不把任意 Markdown、正文片段或推断关系伪装为权威搜索结果，也不实现全文/语义搜索基础设施。

### 文档目录

“文档”页以资料角色和权威层级组织，而不是按文件系统递归平铺：

```text
当前态
  注意力规则
  架构
  领域与需求
  ADR

工作状态
  探路地图与决策
  交付规格与 tickets

演变与证据
  项目历史
  Git 证据

读者与技能资料
  README、长期读者文档、技能
```

- 当前态目录遵守架构索引、领域上下文和显式入口的原始顺序；入口没有列出的已知当前态文件仍可在同组展示，但必须标为“未由入口索引”。
- 工作状态按地图/交付面的显式链接顺序，其次稳定编号文件名排列；历史按既定日期和同日顺序；无显式顺序的对象按规范化仓库相对路径回退。
- 条目只展示定位和判断所需信息：标题、实体类型、资料类别、权威层级、范围、生命周期或有效性、诊断摘要、仓库相对路径和简短摘要。关系数量只是辅助，不能代替来源与权威提示。
- 当前态、工作状态、历史、读者资料和证据永远分组或清晰标识，不能因为标题相近或搜索排序而合并。
- 从目录点击进入已确定的独立阅读页；目录不复制完整正文，也不维护另一份文档状态。

### 搜索范围与字段

全局查找只查询 `ProjectIndex` 已知实体及其结构化投影，覆盖当前态、探路、交付、历史、读者文档、技能、代码锚点和 Git 证据。首版可匹配的字段是：

```text
实体标题
仓库相对路径与规范实体 ID
Markdown 标题目录
实体类型与资料类别
scope、包、领域和权威层级
Decision/Ticket/ADR/Git 的状态和 readiness
历史日期、标签、范围、当前依据和证据标识
正式关系类型、已解析关系目标与代码锚点
```

- 正文段落、任意 frontmatter 键值和未索引 Markdown 不参与首版搜索；用户只记得正文短语时，界面要明确说明“首版仅查结构化字段”，而不是暗示没有相关资料。
- 查询同时支持中文文本、英文大小写不敏感文本和仓库路径片段。查询规范化只处理空白、斜杠、连字符、下划线、常见标点与英文大小写；不承诺中文分词、模糊拼写、同义词、语义匹配或 AI 推荐。
- 多词查询默认要求每个词能在同一实体的可搜索字段中匹配；路径分段可作为同一查询词的匹配单位。
- 过滤器使用实体真实字段：资料类别、实体类型、范围/包/领域、权威层级、解析有效性、生命周期状态、readiness、历史标签、关系类型和解析状态。筛选只改变投影，不改变实体身份或权威顺序。

### 搜索排序与结果解释

结果按确定性匹配等级排序：

1. 标题精确匹配；
2. 实体 ID 或仓库路径的精确片段匹配；
3. 标题目录精确或前缀匹配；
4. 其他结构化字段匹配；
5. 同一等级内依次按权威层级、原始入口/资料顺序、规范化路径排序。

每个结果必须显示至少：

```text
标题
实体类型与资料类别
权威层级或“工作状态/历史/证据”提示
范围或路径
匹配字段
有效性/诊断摘要
```

搜索排序不改变权威事实：历史、工作状态或证据即使文本匹配更强，也必须保持自身的资料标识；当前态冲突仍按项目记忆权威顺序解释。

### 无结果与不完整来源

- 没有结构化匹配时显示原始查询、已应用过滤器、当前搜索字段范围，并提供清除筛选和转到目录的入口。
- 过滤器排除了原本匹配项时，明确说明是过滤导致结果为空。
- 来源未配置时显示“未配置”，不可读取或快照过期时显示来源诊断；搜索不将不可用来源视为不存在。
- 部分有效实体仍可作为结果展示，但必须显示无效字段、未解析关系或阅读限制；无效资料不能获得成功/当前态样式。
- 任意未索引 Markdown 可以作为“未索引文档”候选入口，仅在用户明确切换到该范围时列出其路径和未索引原因；它不进入默认目录、全局搜索或当前态结果。

### 首版范围外

首版不实现：

- Markdown 全文索引、中文分词、模糊搜索、同义词、向量/语义搜索或 AI 问答。
- 跨仓库搜索、网络检索、持久化搜索数据库或后台索引服务。
- 基于标题相似、正文关键词或修改时间的关系推断。
- 把未索引 Markdown 自动提升为资料实体或权威当前态。

若真实项目使用证明结构化搜索不足，后续可以新增独立决策来评估全文索引；它必须保留资料类别、权威提示、来源诊断和确定性回退排序。

## 依据

- 用户确认方案 A：首版采用权威优先目录和跨实体结构化搜索，不从首版实现全文搜索，也不只提供目录。
- [盘点可展示资料与显式关系](01-artifact-contracts.md)：只有契约位置或权威入口可达资料获得结构化身份；当前态、工作状态、历史和证据必须保留不同权威与错误语义。
- [定义项目实体与关系模型](02-entity-relation-model.md)：`ProjectIndex` 提供稳定实体 ID、类别、权威、有效性、状态、关系和确定性 `sourceOrder`，页面投影不得绕过它扫描文件。
- [确定首次打开的信息架构](03-first-open-information-architecture.md)：文档页负责分类、目录、筛选和搜索结果，权威层级可见；首页只给继续阅读入口。
- [确定阅读与上下文交互](04-reading-and-context-interaction.md)：目录和搜索结果都进入可深链接阅读页，保持来源和调查上下文。
