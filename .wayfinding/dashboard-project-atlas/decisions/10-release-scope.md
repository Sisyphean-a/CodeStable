# 确定版本范围与验收切片

## 问题

Dashboard v2 的首个可交付版本应包含哪些完整用户能力、明确推迟哪些能力，并按什么顺序切成可验证的垂直交付，以便后续规格完整但不过度扩张？

## 答案

采用**完整 v2.0 对外发布、四个内部垂直切片实施**。任何只覆盖阅读、历史或统计的中间状态都不是对外的 v2；只有项目理解闭环完整时才替换当前 dashboard。这个范围实现“打开即理解整个项目”，同时避免一次性大改无法定位回归。

### v2.0 必含能力

- 项目导读首页、固定导航和持续可见的当前注意力。
- 当前态、探路、交付、历史、文档和关系六类资料面。
- 独立、深链接的实体阅读页、原始 Markdown 入口和按需信息检查器。
- 权威优先目录、已确认字段的结构化搜索和筛选。
- 语义历史时间线；decision 与 ticket 的行动列表和各自有界 DAG；局部文档关系图与完整文字关系列表。
- 来源、权威、解析状态和可定位诊断；不将未配置、未知、坏链接、冲突或 stale 降级为成功或零进度。
- 同源只读 API、SSE 自动刷新、URL 状态恢复和既定 Node/手工浏览器质量门禁。

### 内部实施切片

| 切片 | 完整用户闭环 | 最低验收证据 |
| --- | --- | --- |
| S1：可信阅读核心 | `ProjectIndex`、诊断、概览、当前态/文档阅读、URL、原文入口与 stale 刷新 | 正常与坏输入 fixture；从首页进入当前态文档，刷新后仍保持上下文。 |
| S2：发现与演变 | 权威目录、结构化搜索/筛选与语义历史时间线 | 可按字段发现实体；未配置来源不显示为零；错误历史行不计入变化并可定位。 |
| S3：当前工作 | 探路/交付行动列表、状态/阻塞原因与分别展开的局部 DAG | 使用 Colombia 形状 fixture 证明 decision/ticket 不混图、图文一致、截断可见。 |
| S4：关系与发布硬化 | 关系页、全部导航闭环、规模 fixture、发布清单和兼容收尾 | 当前 CodeStable、失败 fixture、规模 fixture和 Chrome/Edge 手工清单全部通过。 |

每个切片必须保留前一切片通过的 Node 测试；S4 前不宣称 v2 可发布。S1–S4 是实现顺序，不是独立产品版本或长期双轨支持承诺。

### 迁移与兼容

- 保持 `cs web`、Node.js 20+、`127.0.0.1`、本机只读和无写入端点。
- 保持 `startDashboard`、`createSnapshot` 与 `/api/snapshot`；后者改为 `ProjectIndex` 的兼容投影，可增加 `schemaVersion` 和诊断字段，但不要求既有汇总消费者重写。
- `bin/cs.js` 不扩大职责。S1 起按既定模块边界替换单文件实现；S4 后删除被替代的扫描、内嵌页面和重复 DTO 逻辑。
- 不做数据迁移、持久化索引、feature flag、长期双 dashboard 或不完整 v2 的公开发布。项目文件仍是唯一权威输入。

### 明确延后

首版不包括全文、向量、AI、模糊搜索，推断关系或自动文档修复，默认全局知识图、物理模拟图或无限展开，远程访问、认证、写入、编辑器/终端唤起，浏览器自动化/视觉像素/跨浏览器矩阵，文件监听器/持久化或复杂增量索引，导出、收藏、个性化布局，以及图形视觉感觉的进一步迭代。

### v2.0 发布判断

仅在以下条件全部满足时发布：

1. S1–S4 的行为和最低证据均已完成。
2. Node 契约、HTTP/SSE、安全与性能门禁通过。
3. 当前 CodeStable、Colombia DAG 形状、错误和规模 fixtures 全部通过。
4. Chrome 或 Edge 的桌面/移动手工清单已留有无阻塞记录。
5. 不存在被静默吞掉的输入错误、刷新失败或安全边界回归。
6. `cs web` 的公开边界和既有快照兼容投影无回归。

## 依据

- 用户选择方案 A：完整 v2.0 对外发布，内部按可验证垂直切片推进。
- 用户的首要场景是接手或重新理解整个项目；因此不将缺少探路、交付或关系面的一部分阅读工具发布为 v2。
- [确定首次打开的信息架构](03-first-open-information-architecture.md)、[确定阅读与上下文交互](04-reading-and-context-interaction.md)、[区分时间线、依赖图与关系图](05-temporal-and-graph-views.md) 和 [确定文档发现与搜索边界](06-document-discovery.md) 已将六类资料面、阅读、图和搜索确定为首版体验，不能以范围压缩推迟。
- [确定 dashboard v2 技术边界](08-technical-architecture.md) 已确定可渐进替换的兼容入口、模块边界和无构建策略；[确定质量与验证契约](09-quality-contracts.md) 已确定切片级自动化与手工发布证据。
- 原型和 Colombia 真实样本证明：当前工作与依赖图是项目理解的一部分，不能作为纯统计或后续附加模块。
