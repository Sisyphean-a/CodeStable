# 区分时间线、依赖图与关系图

## 问题

语义历史、Git 证据、决策硬依赖、工单硬依赖和文档关联分别应采用什么视觉与交互模型，才能表达各自真实结构，并让用户看懂演变、前沿、阻塞和关联而不误以为它们是一棵统一的变更树？

## 答案

采用**按真实结构分别表达，并只提供有边界的局部图**。时间、硬依赖和文档关系不是同一种结构；它们不能被合并成“项目变更树”，也不在首页默认渲染为全局知识图。

### 语义历史：时间线与有依据的演变链

- “历史”页的默认视图是按历史格式排序的编辑式**语义时间线**：日期、`功能|缺陷|重构|演进`、结果、范围、原因摘要、当前依据和证据。
- 可按日期、范围、标签、当前依据和规范主题筛选或分组；排序始终遵守月文件日期逆序与同日写入顺序。
- “变更树”只作为某一历史条目的**语义演变链**出现：它连接可解析的 `current-basis`、`supersedes`、显式 Markdown 链接和明确的历史证据。无明确边时保持时间线，不猜测因果或演进关系。
- 演变链按时间纵向排列，边必须标明关系类型；当前态是关联入口，不表示历史条目自动覆盖当前规则。
- Git 不是另一条主时间线或提交树。提交、代码路径和原始来源仅作为历史条目的证据链接与详情，并明确标为 `evidence`。

### 决策与 tickets：行动列表为默认，依赖 DAG 按需展开

- “探路”和“交付”页的默认视图是按行动意义分组的可读列表：

```text
Decision：当前前沿 / 已认领 / 被阻塞 / 已关闭
Ticket：Ready / 已认领 / 被阻塞 / 已关闭
```

- 每一行显示对象标题、生命周期状态、认领者（如有）、直接阻塞原因或可行动原因，以及硬依赖数量；不能只显示百分比或节点数。
- “查看依赖”进入相应类型的有向无环图。Decision 与 Ticket 永不混在同一依赖图内。
- DAG 使用确定性的分层布局：上游依赖在左、被依赖对象在右；边只表示 `depends-on`，箭头方向和图例始终可见。
- 节点标签至少包含标题、状态和 readiness；状态色是辅助信息，文字不可省略。未知、未解析或坏依赖以诊断节点或未解析边显示，绝不渲染为已关闭。
- 默认聚焦一个选中对象及一跳上游和下游；用户可按节点“再展开一层”。初始图最多显示 20 个节点、40 条边。超过上限时，图上说明已显示的确定性范围与剩余数，并引导用户筛选或转为完整文本列表；完整依赖列表始终可访问。
- 支持按状态、认领者、关系方向和解析状态筛选；筛选不会改变原始依赖事实，只改变当前投影。

### 文档与跨对象关联：局部关系图和完整关系列表

- 默认关系入口在阅读页的上下文检查器中显示当前实体的一跳来源、反向引用、当前依据、证据、替代关系和代码锚点；它首先是带文字的关系列表。
- “关系”页才显示局部关系图，以选中实体为中心：入向关系位于左侧，选中对象居中，出向关系位于右侧；边显示 `contains`、`links-to`、`source-of`、`current-basis`、`evidence`、`supersedes`、`code-anchor` 或 `depends-on`。
- 关系图默认一跳，使用同样的 20 节点、40 边上限和手动逐层展开；完整关系文本列表永远不受图上限影响。
- 支持按关系类型、入/出方向、来源类别、权威层级与解析状态筛选。关系图不使用随机或物理模拟布局，保证同一快照中位置与阅读顺序稳定。
- `unresolved`、`external` 和 `unsafe` 关系保留原始目标与解析状态，但没有伪造目标节点或成功跳转；没有显式关系时显示“未发现可验证的关系”，而不是推荐猜测连接。

### 通用交互与可访问性

- 所有时间线条目、列表行、节点和边均链接到已确定的独立阅读页，并使用稳定实体 ID 维持浏览器历史。
- 每种图必须有同等信息的语义化文本列表、筛选状态说明和键盘可达的节点/关系操作；图不是唯一的信息载体。
- 图例、边方向、状态和截断说明始终可见；颜色、位置和 hover 不能是理解关系的唯一手段。
- 自动刷新在当前对象仍存在时保留选中节点、筛选和展开深度；来源变更导致关系失效时显示诊断与过期提示，不无声重排为成功连接。
- 页面采用简洁线条、低饱和状态色和轻边框；不使用大面积色块、会漂移的网络、3D 效果、渐变或无语义装饰。

## 依据

- 用户确认方案 A：结构各自真实表达，图只局部、按需展开；不采用默认全局知识图，也不删除图能力。
- [盘点可展示资料与显式关系](01-artifact-contracts.md)：语义历史、Git、决策依赖、ticket 依赖和文档关系具有不同来源、字段与权威语义；正式关系必须可定位，未解析关系仍需可见。
- [定义项目实体与关系模型](02-entity-relation-model.md)：`Relation.kind`、`provenance`、`resolution`、稳定实体 ID 与各类型 readiness 支持分别投影时间线、DAG 和局部关系图。
- [确定首次打开的信息架构](03-first-open-information-architecture.md)：首页只展示摘要，历史、探路、交付和关系由独立页面承担深读；数字不主导理解。
- [确定阅读与上下文交互](04-reading-and-context-interaction.md)：节点与关系跳转到独立阅读页，检查器提供一跳文字关系，复杂图不挤占正文。
- 用户指定 minimalist UI 规范：图形表达必须克制、稳定、具备文字替代，不能以视觉噱头取代项目语义。
