# 确定首次打开的信息架构

## 问题

在“首次接手或重新理解项目”为首要场景的前提下，首页和全局导航应以什么顺序回答项目身份、范围、当前依据、重要演变、活跃探索、交付状态和继续阅读入口，才能让用户快速形成正确心智模型而不过载？

## 答案

采用**项目导读优先，固定导航负责深挖**的信息架构。首页的任务不是把所有状态并列统计，而是在一次阅读中建立正确心智模型；探路、交付和 Git 是持续可见但次级的当前注意力。

### 首页的阅读顺序

宽屏使用左侧固定导航、中间受限宽度的编辑式正文、右侧当前注意力栏；窄屏把导航收进抽屉，当前注意力顺序移动到项目身份之后。三个区域都服从同一阅读顺序：

1. **项目身份。** 项目名称、简述、仓库根、包/范围概要、当前分支与工作区状态；若名称是目录名回退，必须标明架构索引不可用。
2. **从哪里开始理解。** 按权威加载顺序显示可点击的阅读路径：注意力规则、架构索引、与当前项目相关的包架构页面、领域上下文。每项用一句话说明“为什么先读”，不能只显示文件名或存在性布尔值。
3. **当前项目地图。** 从当前态入口投影范围、包、领域上下文、公开边界和代码锚点，回答“项目由什么组成、现行依据在哪里”。这不是源码树，也不是关系全图。
4. **重要演变。** 显示少量最近且可解析的语义历史，包含变化标签、结果、范围、原因摘要和当前依据入口，回答“为什么现在是这样”。Git 提交只在历史条目的证据或项目身份中出现，不替代语义历史。
5. **当前正在发生什么。** 显示有限的活跃探路前沿、已认领/ready/blocked tickets、未解决诊断和工作区变更；每一项必须显示对象、状态和原因，不能只展示计数或百分比。
6. **继续阅读。** 为当前态、探路、交付、历史、文档和关系提供明确入口；首页只显示摘要，不承载完整对象列表、全文或大型关系图。

首页应以“项目身份”和“从哪里开始理解”构成首屏的叙事重心；当前注意力在宽屏右栏常驻，在小屏进入项目身份之后，但绝不抢占首屏主标题和阅读路径。

### 全局导航与页面职责

固定导航按用户问题组织，而不是按目录机械照搬：

```text
概览        项目导读、阅读路径、当前地图、重要演变和当前注意力。
当前态      权威的注意力、架构、领域与 ADR 入口和正文；优先显示权威顺序。
探路        决策地图、目的地、迷雾、前沿、认领和硬依赖。
交付        规格、tickets、验收、来源、实施前沿和阻塞。
历史        语义变化的时间线与按范围/主题的入口；Git 作为证据，不是主时间线。
文档        资料分类、目录、筛选和搜索结果；权威层级可见。
关系        从一个已选实体展开的局部、带关系类型和来源的探索视图。
```

- 页面地址必须可深链接到选中对象；刷新后保留用户所在页面和对象，不把用户送回概览。
- 页面间使用同一个 `ProjectIndex` 的实体 ID 传递选中对象，避免从标题或显示名称重新猜测目标。
- 当前态、探路、交付、历史和文档页面的具体阅读、详情栏、图交互及搜索细节由后续决策确定；本项只确定其导航职责和首页入口。

### 信息密度与视觉优先级

- 首页使用编辑式段落、短列表、轻分隔线和少量不对称 bento 区块表达层级；数字只能辅助对象文本，不能成为主视觉。
- 活跃工作使用克制的低饱和状态标签；颜色不可作为唯一状态载体。
- 不把每个摘要都包装成卡片，不使用大面积状态色、趋势图、环图或无含义的 KPI。
- 首页最多呈现能帮助首次理解的有限对象；超出数量时显示“查看全部”而不是无界堆叠。

### 空状态、部分状态与错误状态

- 找不到 `.codestable/`：维持现有启动失败，不展示伪项目。
- `attention.md` 缺失：显示“没有注意力规则”，这是可读空状态。
- 架构索引、领域上下文或已被入口引用的当前态文件缺失/无效：概览仍可展示已经验证的环境和资料，但“从哪里开始理解”和“当前项目地图”必须显示具体缺口、受影响范围与诊断入口；不可用目录名冒充当前架构。
- 历史、探路图、交付面、ADR、技能或读者文档缺失：按来源显示“未配置”或“尚无资料”，不显示零进度或健康判断。
- 某个对象、关系或派生状态部分有效：保留可读内容，同时在其来源位置显示诊断摘要并链接到详情；坏依赖不产生 ready 或 frontier。
- 数据源读取失败或自动刷新失败：保留最后一次成功快照，但固定显示“数据已过期”及失败来源；首页不把陈旧快照呈现为实时状态。

## 依据

- 用户明确确认方案 A：首次打开采用项目导读优先，不采用单页长叙事或工作台总览作为主模式。
- [盘点可展示资料与显式关系](01-artifact-contracts.md)：当前态、工作状态、语义历史和 Git 具有不同权威与失败语义；缺失与冲突必须可见。
- [定义项目实体与关系模型](02-entity-relation-model.md)：所有页面由有类型的 `ProjectIndex` 投影，实体 ID 可稳定支持跨页面深链接和诊断。
- `skills/cs-domain/references/memory-model.md`：按范围加载先读 attention、架构索引、包页、领域上下文，历史按需解释原因，不能倒置为首页的文件数量统计。
- 用户指定 minimalist UI 规范：暖色单色、编辑式排版、宏观留白、轻边框和克制状态色；因此首页避免 KPI 大屏和密集看板。
