# 确定阅读与上下文交互

## 问题

用户从概览进入当前态、历史、决策、规格、工单或普通文档后，应如何阅读正文、查看元信息、沿来源与反向引用跳转并保持上下文，才能支持连续调查而不把界面变成复杂 IDE？

## 答案

采用**独立阅读页 + 可选上下文检查器**。阅读正文是首要任务；关系、来源、状态与诊断只在用户主动展开时出现。页面不实现固定多栏 IDE、应用内标签系统或全局浮层预览器。

### 入口与阅读状态

- 从概览、当前态、探路、交付、历史、文档或关系进入任何实体时，都导航到对应页面的可深链接阅读状态。
- URL 必须携带页面视图和稳定实体 ID；页面重载、复制链接、浏览器前进/后退都恢复同一选中对象，而不是按标题重新查找。
- 路由可以使用查询参数或路径段，但必须使用 `ProjectIndex` 的规范化实体 ID，不能泄露 Windows 绝对路径。
- 当目标实体无效、已删除或不可用时，保留来源页面并显示可定位诊断、目标 ID 和可返回入口；不静默跳回概览。

### 桌面布局

```text
固定全局导航 | 主阅读区 | 可选上下文检查器
```

- **全局导航**只负责在概览、当前态、探路、交付、历史、文档和关系之间切换；它不是文件树。
- **主阅读区**默认占据可读宽度，显示一个实体的完整 Markdown 正文或其对应的结构化阅读视图。长文档拥有标题目录、清晰段落层级和原文内显式链接；正文不因常驻元数据面板而被压窄。
- **上下文检查器**默认收起，用户通过明确“信息/关系”操作打开。打开时展示选中实体的类型、权威层级、来源路径、作用范围、生命周期状态、认证前沿/阻塞原因、来源、反向引用、代码锚点、关系诊断和快照状态。
- 检查器只显示当前实体的一跳关系摘要；深层关系和图形探索进入“关系”页面，避免在阅读区塞入大型图。
- 当前页的分类列表或目录由页面自己提供：当前态按权威入口，探路按地图，交付按规格，历史按时间，文档按分类。列表选择改变主阅读区，不创建应用内标签页。

### 跳转、返回与上下文连续性

- 文内显式 Markdown 链接、来源、当前依据、证据、硬依赖、反向引用和代码锚点均以带关系类型的链接呈现；点击后进入目标实体的阅读状态。
- 点击同一页面的对象时，保留列表过滤、排序和滚动位置；跨页面跳转时，浏览器历史保存来源地址。返回操作优先由浏览器 Back 完成，而不是维护另一套隐式调查栈。
- 面包屑只呈现结构归属或当前页面路径，例如“当前态 / 包架构 / 仪表盘包”；它不能伪造用户实际调查路径。来源对象则作为显式“来自”链接展示。
- 关系未解析、外部或不安全时，链接必须显示相应状态；未解析目标不可导航为成功页面。
- 用户要并行对照完整对象时使用浏览器新标签页；dashboard 不实现文档分屏、标签管理或本机工作区。

### 原文、外部定位与安全边界

- 任何可读 Markdown 实体提供“查看原始 Markdown”和“复制仓库相对路径”；原文仍在 dashboard 同源只读页面或下载响应中呈现，并沿用 HTML 转义和内容安全策略。
- 代码锚点、Git 提交和外部链接都展示目标类型与解析状态。仓库内可解析对象进入相应 dashboard 阅读状态；外部目标在新浏览器标签打开，并使用安全的 `noopener` 语义。
- Dashboard 不调用本机编辑器、终端或自定义 URI，不暴露绝对路径，不提供修改、认领或关闭操作。

### 移动端与辅助技术降级

- 小屏以单列阅读页为准：全局导航收进可访问的抽屉；分类列表进入单独的选择页或可折叠区；上下文检查器改为显式“信息”按钮打开的底部抽屉或独立详情页。
- 所有阅读、跳转、返回、检查器开关、目录和复制路径操作必须完整可用键盘完成，并有可见焦点与语义化名称。
- 打开检查器或移动端抽屉时，焦点进入该区域；关闭时回到触发控件。不得以 hover 作为访问关系、诊断或来源的唯一方式。
- `prefers-reduced-motion` 时关闭抽屉与页面切换的非必要动效；阅读位置和焦点不会因自动刷新被强制改变。

### 列表、正文和异常对象

- 列表展示标题、类型、最少必要状态与诊断摘要；完整正文和元信息只在阅读状态展开，避免所有页面重复卡片化。
- 可解析但部分无效的资料仍可阅读，检查器明确列出无效字段和受影响关系。
- 没有正文的结构化实体（如 Git commit 或未解析关系）使用专门的证据/诊断阅读视图，清晰说明没有可读 Markdown，而不是渲染空白文档。
- 自动刷新只更新数据状态提示；如果当前实体仍存在，保持选中、滚动和检查器开关。如果实体消失，保留最后阅读的上下文与“已移除/不可用”说明，并给出安全返回入口。

## 依据

- 用户确认方案 A：阅读页保持正文焦点，上下文检查器按需展开；不采用永久三栏调查工作区或以浮层为主的预览模式。
- [定义项目实体与关系模型](02-entity-relation-model.md)：稳定实体 ID、关系解析状态、来源定位和诊断是一等数据，能够支持深链接、反向引用和失效目标呈现。
- [确定首次打开的信息架构](03-first-open-information-architecture.md)：固定导航按用户问题组织，首页负责项目导读，具体对象必须通过导航后深入阅读，且刷新后保留选中上下文。
- 地图非目标：dashboard 不替代代码编辑器、Git 客户端或项目管理器，不提供写入操作或通用工作区功能。
- 用户指定 minimalist UI 规范：编辑式正文、留白和轻边框优先于常驻多栏密度与大面积状态视觉。
