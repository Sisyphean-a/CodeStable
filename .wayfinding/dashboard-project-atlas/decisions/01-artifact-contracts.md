# 盘点可展示资料与显式关系

## 问题

现有 CodeStable 项目中，dashboard 可以把哪些资料类型、字段、状态和链接当作权威输入；每种输入的缺失、冲突、坏链接、可选目录和兼容格式应如何如实呈现而不猜测成功？

## 答案

Dashboard 只把**由仓库契约确定位置或由权威入口显式链接到的资料**当作结构化输入；任意未链接 Markdown 可以作为“未索引文档”候选，但不能自动获得当前态或权威身份。所有输入都保留来源类别和权威层级，不能合并成一组无差别文档。

### 1. 项目与环境事实

- 项目根以最近的 `.codestable/` 为必要识别条件；不存在时 `cs web` 继续失败退出。
- 当前代码、配置、脚本、目录布局和命令输出是最高优先级的环境事实。Dashboard 首版只读取完成项目理解所需的确定性子集：项目根、包清单和版本、Node 要求、Git 仓库状态，以及当前态文档列出的代码锚点；不递归分析全部源码来猜测架构。
- 项目显示名优先来自 `.codestable/architecture/INDEX.md` 的一级标题；缺失时可回退到目录名，但必须标明这是显示名回退，不代表架构索引有效。

### 2. 项目当前态

以下位置属于当前态资料，权威顺序低于当前代码和明确决定，高于历史与旧工作文档：

- `.codestable/attention.md`：每轮必读注意力规则。
- `.codestable/architecture/INDEX.md`：范围地图、默认加载、公开边界和当前态入口。
- `.codestable/architecture/packages/*.md`：包职责、公开边界、依赖和代码锚点。
- `.codestable/architecture/shared/*.md`：跨包契约、不变量和共享机制。
- `.codestable/requirements/CONTEXT.md`：领域作用域地图、工作区通用语言和稳定规则。
- `.codestable/requirements/contexts/*.md` 与 `shared/*.md`：具体领域上下文及共同拥有的规则。
- `.codestable/requirements/adrs/*.md`：有效或已替代的高代价决定；状态、`superseded-by`、范围、代码锚点和相关历史均为结构化语义。

可可靠提取的共同信息包括仓库相对路径、一级标题、frontmatter 中已声明的 `scope`、`code-paths`、ADR 状态等字段、标题目录、正文和 Markdown 链接。缺少某个可选目录表示“未配置/无此类资料”，不等于解析失败；当前索引引用了不存在的页面时才构成坏链接。

README、包文档索引及其显式链接到的长期读者文档可以展示为“读者文档”，但不因被展示而升级为项目当前态。仓库 `skills/*/SKILL.md` 可以按技能包文档展示其 `name`、`description`、路径和正文，同样保留其“技能”类别。

### 3. 探路工作状态

本地地图位于 `.wayfinding/<map-name>/`：

- `map.md` 提供标题、目的地、非目标、约束、完成判断、覆盖面、迄今决定、打开决策项、迷雾和范围外。
- `decisions/*.md` 提供稳定路径、标题、问题、答案、依据，以及 frontmatter 中的 `处理方式`、`状态`、`认领者`、`硬依赖`。
- `阻塞`、`前沿`和`已认领`不是持久字段，必须从状态、认领者和硬依赖实时派生。
- map 到 decision 的 Markdown 链接、decision 的硬依赖及目录包含关系是正式关系。

`.tmp/` 中的可丢弃会话快照不是稳定规划面，也不在 dashboard 的权威资料范围内。

### 4. 交付工作状态

交付面来自 `.delivery/<name>/` 或 `.wayfinding/<map-name>/delivery/`：

- `spec.md` 的正式段落是问题、目的地、用户可观察行为、实现决定、测试决定、验收标准、范围外和来源。
- `tickets/*.md` 提供标题、交付结果、当前/期望行为、关键契约、验收标准、范围外、实施结果和验证证据，以及 `交付类型`、`状态`、`认领者`、`硬依赖`、`来源规格`。
- `ready`、`claimed` 和 `blocked` 必须从状态、认领者和依赖实时派生。
- 地图到内嵌交付面、规格到来源、ticket 到来源规格、ticket 硬依赖及目录包含关系是正式关系。

### 5. 语义历史与 Git 证据

- `.codestable/history/YYYY-MM.md` 是重要语义变化索引。有效条目必须解析出日期、四类标签之一（`功能`、`缺陷`、`重构`、`演进`）、结果、范围、原因、当前依据和证据；月文件和同日条目遵守既定排序规则。
- 历史条目指向的当前依据、代码路径、提交或原始来源可以形成正式关系；只有文本能够解析为仓库内有效路径、Markdown 链接或有效 Git 对象时，关系才算已解析。
- Git 只提供环境和证据事实：仓库是否可用、当前分支、HEAD/提交、工作区文件状态以及历史证据引用。Git 提交不是 CodeStable 语义历史，不能用提交数量或提交树替代历史条目。

### 6. 可以建立的正式关系

只有以下可定位关系进入正式关系集合：

- Markdown 相对链接及其反向引用。
- 目录契约产生的包含关系，例如地图包含决策项、交付面包含规格和 tickets。
- `硬依赖`、`来源规格`、ADR `superseded-by` 等规范字段。
- 历史中的当前依据与证据、规格中的来源、决定依据中的当前态链接。
- 当前态中明确列出的代码锚点。
- 能验证存在的仓库相对路径、标题锚点和 Git commit。

标题相似、正文关键词相近、文件修改时间接近等启发式结果不能冒充正式关系；若后续保留，只能明确标为建议或推断。

### 7. 缺失、冲突和错误呈现契约

每个来源或对象至少具有 `有效`、`部分有效`、`无效`、`不可用` 四种读取结果，并携带可定位诊断：

- **可选来源缺失：** 显示“未配置”或空状态，不报成功，也不计为零进度。
- **契约要求或已被引用的文件缺失：** 保留未解析关系并报告具体来源、目标和字段；依赖项状态为不确定/阻塞，绝不能视为 ready。
- **frontmatter 缺失、枚举未知或必填段落缺失：** 文档正文仍可阅读，但相关结构化字段标为未知，禁止把未知状态默认为“打开”或“关闭”。
- **历史条目格式错误：** 保留原文和行号诊断，不把仅以日期开头的行计作有效变化。
- **重复稳定身份或同一关系出现冲突目标：** 分别保留对象并报告冲突，不静默覆盖或合并。
- **当前代码、当前态、历史或旧文档互相冲突：** 展示双方来源并按项目记忆权威顺序标明优先级；dashboard 不自行改写资料，也不把旧文档提升为当前事实。
- **路径越界、符号链接或仓库外目标：** 不跟随为项目实体；作为外部或不安全目标显示。
- **读取、编码、权限或 Git 命令失败：** 对应来源标为不可用并显示错误。项目根不可读取时启动失败；自动刷新失败时保留最后一次成功快照，但页面必须显示快照已过期及本次失败，而不是只在终端记录。

当前实现的宽松回退不能成为 v2 契约：缺失 frontmatter 和未知状态目前都会被 `normalizeStatus` 当作打开；日期前缀行会被历史计数；Git 异常被统一压成不可用；刷新失败仅输出终端。这些行为都需要在后续实体模型和质量契约中被显式消除。
