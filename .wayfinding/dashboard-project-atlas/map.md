# Dashboard 项目全景工作台

## 目的地

为现有本地只读 dashboard 得出一条完整、可实施的产品与技术路线，使第一次接手项目或隔一段时间重新进入项目的人，打开面板后能够理解项目是什么、当前有效依据在哪里、项目如何演变、当前有哪些探索与交付，以及如何沿显式关系继续调查。

面板以项目理解为第一目标，以当前注意力为辅助；最终路线必须能直接折叠为实施规格，不再遗留目的地范围内的产品、交互、信息、视觉、架构或质量裁决。

## 非目标

- 不把 dashboard 变成远程服务、多人协作平台或带认证的托管产品。
- 不在面板中认领、关闭或修改决策项、工单、项目记忆、Git 或其他项目文件。
- 不替代代码编辑器、Git 客户端、Issue Tracker 或通用项目管理工具。
- 不把所有对象默认铺成大型知识图谱，也不以统计大屏作为主要体验。
- 不依靠 AI 猜测或未标明的启发式关联冒充权威项目关系。

## 约束

- 保持现有公开边界：`cs web`、Node.js 20+、只监听 `127.0.0.1`、本地只读、无写入端点，并保留项目文件变化后的自动刷新。
- 当前代码以 `dashboard/src/dashboard.js` 单文件实现扫描、快照、HTTP/SSE 和页面；路线可以决定拆分，但不得无目的增加框架、依赖或长期流程。
- 项目当前态、历史、探路图和交付面的语义必须遵守 `.codestable` 当前规则及对应格式，不能把 Git 过程、语义历史、决策依赖和交付依赖混为一种时间线或树。
- UI 必须遵守 [Premium Utilitarian Minimalism & Editorial UI](https://github.com/Leonxlnx/taste-skill/blob/main/skills/minimalist-skill/SKILL.md)：暖色单色、编辑式排版、宏观留白、轻边框、克制的低饱和状态色、扁平组件；禁止渐变、霓虹、重阴影、玻璃拟态、大面积主色、通用 SaaS 装饰和 emoji。规范内部冲突时，以 Absolute Negative Constraints 为准。
- 首页优先服务“接手或重新理解项目”，日常行动只作为持续可见的辅助信息。
- 正式关系必须来自可定位的 frontmatter、Markdown 链接、当前依据、来源、证据、代码锚点或 Git 事实；推断关系若保留，必须与权威关系明确区分。

## 完成判断

- 能列出 dashboard 读取的全部权威对象、字段、状态和显式关系，并说明缺失、冲突、坏链接与未知格式如何呈现。
- 已确定首页、全局导航、当前态、探路、交付、历史、文档和关系探索的职责、信息层级与跨页面行为。
- 已确定语义历史、Git 证据、决策依赖 DAG、工单依赖 DAG 和文档关系图各自的视觉模型，不再把它们误称或渲染为同一种“变更树”。
- 已有经过用户判断的低成本界面原型，证明首次打开时能理解项目，并符合指定 minimalist UI 规范。
- 已确定实体与关系模型、解析边界、前后端模块边界、依赖策略、刷新与错误模型。
- 已确定可访问性、响应式、性能、数据规模、测试与验收标准。
- 已确定首个可交付版本与后续阶段边界，实施规格无需再补产品或技术裁决。

## 迄今决定

- 首页以项目理解为主，当前行动作为右侧或次级注意力信息持续可见。
- 采用编辑式极简视觉语言；禁止项优先于规范中相冲突的装饰建议。
- [盘点可展示资料与显式关系](decisions/01-artifact-contracts.md) - 只结构化读取契约位置和权威入口可达资料；保留来源层级，仅从显式字段、链接、目录契约、代码锚点和有效 Git 证据建立正式关系，所有缺失、冲突和解析失败均产生可定位诊断。
- [定义项目实体与关系模型](decisions/02-entity-relation-model.md) - 采用有类型的只读 `ProjectIndex`：资料源只解析一次，实体保留来源、权威和各自生命周期，正式关系携带依据与解析状态，诊断是一等数据，各页面只从统一索引生成投影。
- [确定首次打开的信息架构](decisions/03-first-open-information-architecture.md) - 首页采用项目导读优先：依次解释项目身份、权威阅读路径、当前项目地图、语义演变、当前注意力和继续阅读；固定导航按用户问题进入各类深读页面，缺失与过期资料必须明确可见。
- [确定阅读与上下文交互](decisions/04-reading-and-context-interaction.md) - 对象进入独立、可深链接的阅读页，正文优先；宽屏按需展开一跳来源、状态、关系和诊断检查器，移动端降级为单列和显式详情入口，不实现 IDE 式常驻多栏或应用内标签。
- [区分时间线、依赖图与关系图](decisions/05-temporal-and-graph-views.md) - 历史默认使用语义时间线与有依据的演变链，decision/ticket 默认使用行动列表并按需展开各自 DAG，文档关系默认文字列表并按需展开局部图；所有图均有确定性布局、逐层展开、20 节点/40 边上限和完整文本替代。
- [确定文档发现与搜索边界](decisions/06-document-discovery.md) - 首版以权威优先目录和跨实体结构化搜索帮助发现资料：仅搜索 `ProjectIndex` 字段，明确结果来源与权威，支持中文、英文和路径片段及真实字段筛选；不做全文、语义、模糊或 AI 搜索。
- [制作并判断低成本界面原型](decisions/07-interface-prototype.md) - 用户通过基于真实 08 哥伦比亚包的原型：短标签首页、阅读页与按需检查器、真实 decision/ticket 依赖图和状态工作线均可行；图的语义必须保留，具体视觉感觉可在实施中迭代。
- [确定 dashboard v2 技术边界](decisions/08-technical-architecture.md) - 采用模块化 Node 服务端与原生 ESM 客户端、无构建步骤和 `markdown-it` 单一生产依赖；`ProjectIndex` 是唯一解析入口，原生 SVG 绘制有界图，完整重建原子换快照、失败保留 stale 快照，URL 承担可共享状态。
- [确定质量与验证契约](decisions/09-quality-contracts.md) - 以 Node 契约、HTTP/SSE、安全和页面投影测试为强制门禁，不引入 Playwright；Chrome/Edge 的桌面、移动、键盘、刷新和极简视觉由有记录的手工发布清单验收，性能 fixture 固定为 250 资料源、100 工作项、2,000 历史和 1,000 关系。
- [确定版本范围与验收切片](decisions/10-release-scope.md) - 对外仅发布覆盖完整项目理解闭环的 v2.0；内部依次交付可信阅读核心、发现与演变、当前工作、关系与发布硬化四个切片，保持 `cs web` 和快照兼容投影，明确延后 AI/全文搜索、写入、全局图和浏览器自动化。

## 迷雾

暂无。当前可见未知均已形成可处理的决策项；扫描中出现新的资料类型、规模风险或交互前置时再补入。

## 范围外

- 远程访问与认证：违反当前本机环回公开边界，且不是项目理解场景的必要条件。
- 面板内编辑、认领和关闭：会让 dashboard 成为绕过技能和规划面纪律的写入旁路。
- 通用代码浏览器和完整 Git 图形客户端：已有专用工具，dashboard 只保留项目理解所需的代码锚点和证据入口。
- 自动生成或修复项目文档：属于其他技能和实施流程，不由只读面板承担。
