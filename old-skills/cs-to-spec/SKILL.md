# 验收合成

只在已确认输入存在 **synthesis debt** 时建立实施契约：补足缺失的稳定来源，或合成不能由拆票阶段机械登记的交付判断。规格是验收清单和来源索引，不是决策正文的副本。

开始前，只读[项目记忆模型](../../cs-domain/references/memory-model.md)的“按范围加载”小节，并按该顺序取得相关当前态；读取[交付面格式](../cs-to-tickets/references/delivery-surface.md)的验收契约。来源是本地决策地图时，先查看[本地地图格式](../cs-wayfinder/references/local-map.md)。

## Synthesis debt

按交付面格式的“交付就绪”判断 ticket-ready 与 synthesis debt。本技能只合成 debt：建立缺失的稳定契约，组合跨来源结果，收敛横切门禁或把原型绑定属性转成验收；来源已有细节继续由直接链接拥有。

规格属于交付工作状态，不进入 `.codestable`。优先写入用户指定位置或来源规划面；来源是本地决策地图时写入该地图的 `delivery/spec.md`，没有规划面时使用 `.delivery/<name>/spec.md`。

## 步骤

1. **定源。** 确认范围、权威顺序和全部直接来源；地图中的打开项、迷雾、失效链接或冲突形成准确缺口并停止。**完成条件：每条来源可达，范围内结论均已确认。**
2. **判债。** 逐项判断结果能否由单一来源机械登记，以及是否存在横切门禁、来源合并或原型晋升。**完成条件：每项 synthesis debt 都有具体合成对象；没有 debt 时已确认输入 ticket-ready，并停止交给 `cs-to-tickets`。**
3. **定锚。** 按范围读取当前代码，识别公开边界、保持契约和最高稳定测试接缝。**完成条件：每项变化都能区分现状、目标和必须保持的行为。**
4. **合成。** 按验收契约建立稳定 AC 和直接来源，横切门禁也进入注册表。**完成条件：每个范围内结果都有满足验收契约的 AC，并能从真实接缝判断成败。**
5. **晋升原型。** 原型影响验收时，把绑定属性写成可独立判断的结构、交互和视觉 AC；需要持久视觉基线时取得用户明确同意再晋升资产，其余属性标为非绑定。**完成条件：原型分支满足交付就绪契约。**
6. **发布。** 按交付面模板写入精简规格。**完成条件：模板各节完整，每个 AC 和来源链接可达，规格没有复制来源正文。**
7. **反查。** 从目的地和每条来源双向检查 AC、横切契约与范围外。**完成条件：每项范围内来源恰有验收归属，没有遗漏、重复权威、无来源要求或仍需裁决的措辞。**

## 完成条件

存在 synthesis debt 时，规划面中只有一份精简现行规格，所有 AC 原子、带稳定 ID 和直接来源；不存在 debt 时没有创建重复规格。返回规格或 ticket-ready 来源，并提示用户显式调用 `cs-to-tickets`；本次不拆工单或修改代码。
