# 视觉讲解

让用户先看懂形状，再按需追踪证据。回答是展示，不是文章。

## 步骤

1. **定点。** 把当前讨论拆成一个或多个可独立展示的问题，并选定主问题。项目问题先核实真实入口、关键节点、分支、结果和必要意图；通用问题使用当前对话与权威来源。只保留会改变答案形状的事实。**完成条件：问题清单、主问题和事实来源均已明确。**
2. **选形。** 选择能独立讲清关键点的最小视图；一个视图只回答一个问题：
   - 逻辑或算法：伪代码；
   - 运行路径：调用树；
   - UI 结构：组件树，并标出相关状态与模块边界；
   - 文件职责或宽范围重构：浅文件树；
   - 组件交互、控制流或数据流：Mermaid；
   - 现有形状上的变化：与主题同形的 `diff`；
   - 大部分内容为新增、上下文决定所有权或顺序，或用户需要可复制目标：完整代码块；
   - UI 布局、状态对比或 Mermaid 会变得拥挤的概念：聚焦 HTML。
   视图仍然拥挤时，按问题拆成多个小视图；需要跨视图浏览或比较时改用 HTML。**完成条件：每个视图都有唯一问题，展示内容只含回答所需的调用、文件、属性、状态和边界。**
3. **展示。** 直接从视图开始，或只用一行标题引出视图。每个视图旁的文字采用 `图注`：最多三条、每条一个句子，按需各写一条结论、证据和边界；每条都必须能指回相邻视图中的节点、连线、区域或差异。每组项目事实在节点标签或证据图注中绑定仓库相对路径与符号，已确认意图绑定决定来源；当前行为、已确认意图和推测使用不同标签。多个问题使用多个“标题 → 视图 → 图注”块。**完成条件：移除任一视图后，其相邻文字便失去依托；每组项目事实均可定位，图外没有可独立成篇的正文。**

## HTML 分支

HTML 是本轮可视化，不是长期文档：

- 只创建一个 `.tmp/show-me-<topic>.html`，CSS 与必要脚本内联，使文件可直接打开。
- 选择图解、信息图或短幻灯片中最贴合问题的一种；使用真实标签和数据。
- 项目相关内容沿用产品的颜色、字体、间距和组件；桌面与窄屏都能读清主路径。
- 文字作为节点、标签、图例、注释或对比项进入展示；视觉层级承担阅读顺序。
- 生成后用系统默认浏览器打开并确认文件可访问。聊天回复只保留一句交付说明和文件路径，展示内容留在 HTML 中。

**完成条件：HTML 已打开，用户无需回到聊天阅读补充长文即可看懂目标问题。**

## 完成条件

用户能从展示本身复述关键关系；每条文字都有相邻视觉归属，项目事实可定位，未知项已标记；临时文件只位于 `.tmp/`，业务代码、项目当前态和长期读者文档保持不变。
